TEORÍA FUNDAMENTAL

Anatomía del Modelo Relacional

Entidad (Tabla)

Cualquier objeto o sujeto del mundo real del cual se recolecta información (ej: usuarios, productos, ventas).

Atributo (Columna / Campo)

Propiedad o característica cuantificable que describe a la entidad (ej: documento, nombres, precio).

Tupla (Fila / Registro)

Una instancia individual, única y concreta guardada en la tabla.

INTEGRIDAD RELACIONAL

Llave Primaria (PK) vs Llave Foránea (FK)

PK

Primary Key (Llave Primaria)

Identificador Unívoco Obligatorio

Columna que asegura que ningún registro sea idéntico a otro en la tabla.

Regla 1: Debe ser ÚNICA (sin duplicados).
Regla 2: NUNCA NULL (Not Null).
Regla 3: INT AUTO_INCREMENT recomendado.
FK

Foreign Key (Llave Foránea)

Vínculo de Integridad Referencial

Columna en una tabla hija que apunta a la PK existente en la tabla padre.

Evita registros huérfanos en la base de datos.
Mismo tipo de dato de la PK padre (INT con INT).
Reglas: RESTRICT / CASCADE.
categorias (Tabla Padre)

nombre : VARCHAR(60)
Relación 1 a Muchos (1 : N)
ON DELETE RESTRICT
productos (Tabla Hija)
🔑 id : INT (PK)
🔗 categoria_id : INT (FK)
MODELADO CONCEPTUAL

Cardinalidades en el Diseño Relacional

1 : 1 Uno a Uno

Usuario ↔ Perfil

Un usuario tiene un único perfil biométrico/médico, y ese perfil le pertenece a un solo usuario.

Solución: La FK se coloca en cualquiera con restricción UNIQUE.
1 : N Uno a Muchos

Categoría ↔ Productos

Una categoría contiene muchos productos, pero cada producto pertenece a una sola categoría.

Solución: La FK siempre va en el lado de los Muchos (productos).
N : M Muchos a Muchos

Ventas ↔ Productos

Una venta contiene varios productos, y un producto se vende en múltiples facturas.

Solución: Requiere Tabla Intermedia (detalle_ventas).
SQL DDL

Definición de Datos: Sentencias y Tipos

Tipos de Datos Estándar en MySQL 8

VARCHAR(n) Texto de longitud variable (documentos, nombres, correos). Solo consume los bytes usados.
INT / BIGINT Enteros para llaves primarias autoincrementales y cantidades de inventario.
DECIMAL(10, 2) ¡Precisión monetaria exacta! Nunca uses FLOAT ni DOUBLE para dinero o precios.
BOOLEAN / TINYINT(1) Banderas lógicas de estado (1 = Activo, 0 = Inactivo).
Sintaxis Base DDL 
-- Crear y usar base de datos institucional
CREATE DATABASE IF NOT EXISTS sistema_ventas_db
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

USE sistema_ventas_db;

CREATE TABLE usuarios (
    id INT AUTO_INCREMENT PRIMARY KEY,
    documento VARCHAR(20) NOT NULL UNIQUE,
    nombres VARCHAR(100) NOT NULL,
    email VARCHAR(120) NOT NULL UNIQUE,
    rol ENUM('ADMIN', 'VENDEDOR', 'CLIENTE') DEFAULT 'CLIENTE',
    activo BOOLEAN NOT NULL DEFAULT TRUE,
    creado_en TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;
INTEGRIDAD

Las 6 Restricciones (Constraints) de Integridad

PRIMARY KEY

Identificador único irrepetible de fila. Implica obligatoriamente UNIQUE y NOT NULL.

NOT NULL

Exige que el campo siempre contenga un dato válido (rechaza valores nulos o vacíos).

UNIQUE

Garantiza que ningún valor se repita en la columna (cédula, correo electrónico, código de barras).

DEFAULT

Asigna un valor predeterminado si el INSERT no lo especifica (DEFAULT TRUE).

FOREIGN KEY

Asegura la relación con la tabla padre e impide que existan registros huérfanos.

CHECK

Valida una condición lógica de negocio (ej: CHECK (precio >= 0)).

LIVE CODING

Creación de Tabla Productos con FK Segura

MySQL 8 / InnoDB
tabla_productos.sql 
CREATE TABLE productos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    codigo_barras VARCHAR(50) NOT NULL UNIQUE,
    nombre VARCHAR(120) NOT NULL,
    precio DECIMAL(10, 2) NOT NULL,
    stock INT NOT NULL DEFAULT 0,
    categoria_id INT NOT NULL,
    creado_en TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    -- Definición de la Llave Foránea con regla de protección
    CONSTRAINT fk_productos_categorias
        FOREIGN KEY (categoria_id) 
        REFERENCES categorias(id)
        ON UPDATE CASCADE      -- Si cambia la PK padre, se replica en cascada
        ON DELETE RESTRICT,    -- ¡BLOQUEO! Protege contra borrados de categorías con productos
        
    CONSTRAINT chk_precio_positivo CHECK (precio >= 0),
    CONSTRAINT chk_stock_positivo CHECK (stock >= 0)
) ENGINE=InnoDB;
ON UPDATE CASCADE: Actualización sincronizada si la llave principal de la categoría llegase a modificarse.
ON DELETE RESTRICT: Previene la existencia de productos huérfanos. Rechaza el borrado de la categoría padre mientras tenga productos vinculados.
SQL DML

Manipulación de Datos: INSERT INTO Seguro

Inserción Múltiple

INSERT INTO categorias (nombre, descripcion) VALUES

('Papelería', 'Útiles de oficina y cuadernos');

-- Inserción en Productos (Referenciando categoria_id existente)

('TECH-002', 'Mouse Ergonómico', 75000.00, 25, 1),
('PAP-001', 'Resma de Papel Carta', 24000.00, 50, 2);

Especificación Explícita de Columnas

Siempre declara los nombres de columnas: INSERT INTO tabla (col1, col2). Esto protege el software ante modificaciones estructurales futuras.

Error por Foreign Key Inexistente

Si intentas insertar un producto con categoria_id = 999:
Error Code: 1452. Cannot add or update a child row: a foreign key constraint fails.

ALERTA CRÍTICA

El Peligro del UPDATE y DELETE sin WHERE

"Nunca ejecutes un UPDATE o DELETE sin la cláusula WHERE"

Omitir el filtro afectará a absolutamente todas las filas de la base de datos de producción.

ERROR FATAL (DESPIDO INMEDIATO) 
DELETE FROM usuarios;
-- ¡Borra la base de datos de clientes entera!

UPDATE productos SET precio = 0;
-- ¡Cambia el precio de todos los productos a 0!
SINTAXIS SEGURA PROFESIONAL 
DELETE FROM usuarios 
WHERE id = 4;

UPDATE productos 
SET precio = 195000.00 
WHERE codigo_barras = 'TECH-001';
