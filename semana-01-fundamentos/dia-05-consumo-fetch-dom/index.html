Arquitectura Web Evolución del Cliente Web

El Frontend y la Red: De Páginas Estáticas a SPAs

Comprender cómo interactúan el cliente (navegador) y el servidor mediante solicitudes asíncronas.

Modelo Tradicional (Multi-Page / Recarga Total)

Cada clic en un enlace o envío de formulario <form action="..."> envía una solicitud que destruye la página actual y descarga un nuevo documento HTML completo.

  • Parpadeo visual molesto (*flicker*).
  • Pérdida del estado de la memoria del cliente.
  • Alto consumo de ancho de banda transfiriendo HTML redundante.
Modelo Moderno (SPA con Fetch API & DOM)

La página inicial se carga una sola vez. Las acciones del usuario disparan peticiones fetch() que viajan en segundo plano transportando solo JSON ligero.

  • Cero recargas de pantalla (e.preventDefault()).
  • Experiencia fluida idéntica a una aplicación de escritorio.
  • Actualización quirúrgica solo en los nodos del DOM que cambiaron.

Sintaxis Fundamental Estándar Web Moderno

Anatomía de la fetch() API Nativa

Función global incorporada en todos los navegadores modernos y en Node.js 18+. Retorna una Promesa que resuelve a un objeto Response. 

// Sintaxis estándar con async / await
async function obtenerProductos() {
  try {
    // 1. Inicia la petición de red (por defecto es método GET)
    const respuesta = await fetch('http://localhost:3000/api/productos');

    // 2. El objeto Response contiene metadatos de cabecera
    console.log('Status HTTP:', respuesta.status); // ej: 200
    console.log('¿Fue exitoso?:', respuesta.ok);     // boolean: true / false

    // 3. Extracción asíncrona del cuerpo serializado en JSON
    const datos = await respuesta.json();
    return datos;

  } catch (error) {
    // 4. Captura EXCLUSIVAMENTE errores de red (ej: sin conexión o DNS)
    console.error('Fallo de red:', error.message);
  }
}
fetch(url, [opciones])

El primer parámetro es el endpoint. El segundo (opcional) define método, headers y cuerpo.

await respuesta.json()

Consume el flujo de bytes de la respuesta y lo transforma en un objeto o arreglo de JavaScript utilizable.

Doble Await

Se requiere await tanto para esperar las cabeceras HTTP de fetch() como para esperar la deserialización del stream con .json().

Trampa Crítica de Red Concepto Esencial de Evaluación

¿Por qué fetch() NO rechaza la promesa en errores 404 o 500?

Uno de los errores más comunes en aprendices de desarrollo web es asumir que un error HTTP viaja al bloque catch.

❌ Error Clásico de Principiante 
try {
  // Si el servidor responde 404 Not Found o 500 Internal Error:
  const res = await fetch('/api/productos/999');
  
  // ¡ESTA LÍNEA SE EJECUTA IGUALMENTE!
  // fetch considera que la comunicación HTTP fue exitosa.
  const data = await res.json();
} catch (err) {
  // ⚠️ NUNCA ENTRA AQUÍ ante un error 404 o 500
  console.log('Error capturado:', err);
}
✅ Patrón Profesional Defensivo 
try {
  const res = await fetch('/api/productos/999');

  // VERIFICACIÓN MANUAL OBLIGATORIA CON res.ok:
  // res.ok es true solo si el status está entre 200 y 299
  if (!res.ok) {
    const errorBody = await res.json();
    throw new Error(errorBody.error || `HTTP ${res.status}`);
  }

  const data = await res.json();
  return data;
} catch (err) {
  // ✅ Ahora sí captura tanto fallos de red como errores HTTP
  mostrarAlertaAlUsuario(err.message);
}

Lectura de Datos (GET) Consumo y Extracción

Peticiones GET: Extracción y Query Parameters

Construcción de URLs dinámicas para filtrar por texto o categorías sin recargar la página. 

// Función genérica para listar o filtrar productos desde el backend
async function consultarProductos(categoria = '', busqueda = '') {
  // 1. Usar URL y URLSearchParams nativos para evitar concatenaciones inseguras
  const url = new URL('http://localhost:3000/api/productos');
  if (categoria && categoria !== 'TODAS') url.searchParams.append('categoria', categoria);
  if (busqueda) url.searchParams.append('q', busqueda);

  console.log('Consultando URL:', url.toString());
  // Genera: http://localhost:3000/api/productos?categoria=HARDWARE&q=teclado

  const respuesta = await fetch(url);
  if (!respuesta.ok) throw new Error('Error al listar inventario');

  const { datos } = await respuesta.json();
  return datos; // Retorna el arreglo de objetos de productos
}
Buenas Prácticas: Utiliza siempre new URLSearchParams() para que caracteres especiales (espacios, tildes, símbolos) se codifiquen automáticamente de manera segura en la URI.

Envío de Datos (POST) Creación de Recursos

Peticiones POST: Headers y Serialización JSON

Para enviar un cuerpo al servidor Express, se deben configurar obligatoriamente tres elementos: método, headers de contenido y serialización. 

async function crearProducto(nuevoProducto) {
  const respuesta = await fetch('http://localhost:3000/api/productos', {
    // 1. Especificar el verbo HTTP en mayúsculas
    method: 'POST',

    // 2. Cabeceras: Avisa a Express que el payload enviado es JSON (activa express.json())
    headers: {
      'Content-Type': 'application/json'
    },

    // 3. Serializar el objeto de JavaScript a una cadena de texto JSON
    body: JSON.stringify(nuevoProducto)
  });

  const data = await respuesta.json();

  // 4. Validar código 201 Created vs 400 Bad Request / 409 Conflict
  if (!respuesta.ok) {
    throw new Error(data.error || `Fallo al registrar: HTTP ${respuesta.status}`);
  }

  return data; // Producto creado con su ID generado por el backend
}
Content-Type: application/json Si olvidas este header, el middleware express.json() del servidor ignorará el body y req.body llegará como undefined.
JSON.stringify(objeto) No puedes enviar un objeto plano directo en body: objeto. La red solo transmite streams de texto serializado o binarios.

Formularios Web Modernos Control de Eventos

Formularios: e.preventDefault() y la clase FormData

Cómo capturar datos de un formulario de forma limpia y profesional sin escribir decenas de document.getElementById(). 

const formulario = document.querySelector('#form-producto');

formulario.addEventListener('submit', async (e) => {
  // 1. OBLIGATORIO: Evitar la recarga automática del navegador
  e.preventDefault();

  // 2. Extraer todos los campos automáticamente mediante la API FormData
  const formData = new FormData(formulario);

  const producto = {
    nombre: formData.get('nombre').trim(),
    sku: formData.get('sku').trim().toUpperCase(),
    categoria: formData.get('categoria'),
    precio: Number(formData.get('precio')),
    stock: Number(formData.get('stock'))
  };

  // 3. Validación en el cliente antes de consumir la red
  if (!producto.nombre || !producto.sku || producto.precio <= 0) {
    alert('Por favor diligencie todos los campos requeridos con valores válidos');
    return;
  }

  // 4. Enviar a la API con fetch POST
  await enviarProductoAlServidor(producto);
  formulario.reset(); // Limpiar campos tras registro exitoso
});

Renderizado Dinámico Document Object Model

Manipulación Moderna del DOM con Template Literals

Generar componentes HTML reutilizables, legibles y dinámicos a partir de colecciones de datos en memoria. 

function renderizarProductos(productos) {
  const contenedor = document.querySelector('#grid-productos');

  // Limpiar contenido previo para evitar duplicados
  contenedor.innerHTML = '';

  // Iterar y crear elementos utilizando Template Literals y Tailwind CSS
  productos.forEach(prod => {
    const card = document.createElement('div');
    card.className = 'p-5 bg-slate-900 border border-slate-800 rounded-2xl space-y-3';
    
    card.innerHTML = `
      <div class="flex justify-between items-center text-xs">
        <span class="font-mono text-slate-400">${prod.sku}</span>
        <span class="px-2 py-0.5 rounded bg-blue-900/50 text-blue-300 font-bold">${prod.categoria}</span>
      </div>
      <h3 class="font-bold text-white text-base">${prod.nombre}</h3>
      <p class="text-xl font-black font-mono text-emerald-400">$ ${prod.precio.toLocaleString()}</p>
      <div class="pt-2 border-t border-slate-800 flex justify-between items-center text-xs">
        <span class="text-slate-400 font-mono">Stock: ${prod.stock}</span>
        <button onclick="actualizarStock(${prod.id})" class="px-3 py-1 bg-slate-800 hover:bg-slate-700 rounded-lg text-slate-200">
          + Stock
        </button>
      </div>
    `;

    contenedor.appendChild(card);
  });
}

Actualización Parcial (PATCH) Mutación de Recursos

Peticiones PATCH: Actualizaciones Parciales en Tiempo Real

Modificar campos específicos (como el stock o estado de inventario) sin tener que reenviar el objeto completo. 

async function modificarStock(idProducto, nuevoStock) {
  try {
    const res = await fetch(`http://localhost:3000/api/productos/${idProducto}/stock`, {
      method: 'PATCH',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ stock: nuevoStock })
    });

    if (!res.ok) {
      const errorData = await res.json();
      throw new Error(errorData.error || 'No se pudo actualizar el stock');
    }

    // Actualización reactiva en memoria para reflejar el cambio inmediato
    const productoLocal = estadoApp.productos.find(p => p.id === idProducto);
    if (productoLocal) {
      productoLocal.stock = nuevoStock;
      renderizarProductos(estadoApp.productos);
    }

    mostrarNotificacionToast('Stock actualizado correctamente (200 OK)');

  } catch (error) {
    mostrarNotificacionToast(error.message, 'error');
  }
}

Diseño de Experiencia (UI/UX) Estados de Interfaz

Los 4 Estados Fundamentales de la Interfaz Asíncrona

Una interfaz profesional nunca deja al usuario esperando a ciegas sin retroalimentación visual.

1. CARGANDO (Loading)

Spinners / Skeletons

Mostrar animación mientras la promesa de fetch() está pendiente. Ocultar los datos anteriores.

2. ÉXITO (Success)

Contenido Renderizado

La petición resolvió con res.ok = true y hay datos disponibles para iterar y mostrar en el catálogo.

3. VACÍO (Empty State)

Sin Resultados

La consulta fue exitosa pero retornó 0 elementos. Mostrar mensaje amigable: "No hay productos en esta categoría".

4. ERROR (Error State)

Fallo de Red o API

El servidor está apagado o retornó código 500. Notificar con banner de alerta o Toast y botón de "Reintentar".

Seguridad Web & CORS Cross-Origin Resource Sharing

Arquitectura Cliente-Servidor y el Mecanismo CORS

Por qué ocurre el error "Blocked by CORS policy" al conectar el Frontend con el Backend en puertos diferentes.

¿Qué es la Política de Mismo Origen (SOP)?

Por seguridad, el navegador bloquea las peticiones de JavaScript que intenten leer datos de un origen diferente (diferente protocolo, dominio o puerto).

Cliente (Frontend): http://127.0.0.1:5500
Servidor (Express): http://localhost:3000
→ ¡Diferente puerto = Origen Cruzado!

Solución: Habilitar Cabeceras CORS en Express

El servidor Express debe enviar la cabecera HTTP autorizando el acceso al navegador: 

// Middleware CORS nativo en Express:
app.use((req, res, next) => {
  res.header('Access-Control-Allow-Origin', '*');
  res.header('Access-Control-Allow-Headers', 'Content-Type');
  res.header('Access-Control-Allow-Methods', 'GET, POST, PATCH, DELETE');
  next();
});
