JavaScript en el navegador es monohilo (single-threaded). Para no congelar la pantalla del usuario mientras viaja la información por la red, las peticiones HTTP se delegan al motor asíncrono del navegador (Web APIs).

BLOQUE 1 Evolución de Estándares Web
SLIDE 05 / 25

De XMLHttpRequest a la Fetch API Nativa Moderna

Antes de 2015, consumir un servicio REST requería código verboso basado en eventos con XMLHttpRequest. Hoy, la Fetch API es el estándar nativo de todos los navegadores modernos.

XMLHttpRequest (Legado 2000 - 2015) Callback Hell 
// Código engorroso basado en eventos
var xhr = new XMLHttpRequest();
xhr.open('GET', 'http://localhost:3000/api/productos', true);
xhr.onreadystatechange = function () {
  if (xhr.readyState === 4 && xhr.status === 200) {
    var data = JSON.parse(xhr.responseText);
    console.log(data);
  }
};
xhr.onerror = function() { console.error("Error"); };
xhr.send();

Requiere manejar estados manuales (readyState 4), callbacks anidados y parsing manual con JSON.parse().

Fetch API + async/await (Estándar ECMAScript) Limpio y Expresivo 
// Código moderno, legible y secuencial
async function obtenerProductos() {
  try {
    const res = await fetch('http://localhost:3000/api/productos');
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const data = await res.json();
    console.log(data.datos);
  } catch (error) {
    console.error('Error de red:', error.message);
  }
}

Basado 100% en Promesas. Se integra de manera perfecta con try...catch sin librerías externas.

¿Por qué aprender Fetch nativo antes de Axios o React? Entender cómo dialoga el navegador nativamente con HTTP te permitirá dominar cualquier librería moderna (Axios, React Query, RTK Query, Next.js) sin verlas como una "caja mágica".
BLOQUE 1 Petición GET Inicial
SLIDE 06 / 25

La Estructura de Fetch: ¿Por qué necesitamos DOS `await`?

Uno de los errores más comunes en aprendices junior es pensar que un solo await entrega los datos finales. HTTP separa los encabezados del cuerpo del mensaje.

recursos/cliente.js (o dentro de <script> en 02-catalogo.html) Enlazado con <script src="cliente.js"></script> 
async function consultarCatalogo() {
  try {
    // 1️⃣ PRIMER AWAIT: Espera la llegada de los Headers HTTP
    const res = await fetch('http://localhost:3000/api/productos');

    // 2️⃣ VALIDACIÓN: Verifica si el status está en rango 200-299
    if (!res.ok) {
      throw new Error(`Error en servidor: Status ${res.status}`);
    }

    // 3️⃣ SEGUNDO AWAIT: Espera y convierte el stream de bytes a JSON
    const resultado = await res.json();

    // 4️⃣ USO DEL PAYLOAD: Acceso directo a los datos
    console.log("Productos recibidos:", resultado.datos);
    return resultado.datos;

  } catch (error) {
    console.error("Fallo de conexión:", error.message);
  }
}
1

Primer await (Llegan los Headers)

La promesa se resuelve en cuanto el servidor envía la primera línea de estado y los encabezados (Status: 200 OK, Content-Type). El cuerpo todavía está viajando en paquetes TCP.

2

Segundo await (Llega el Body)

El método res.json() lee el stream completo del cuerpo de la respuesta y lo transforma asíncronamente en un objeto/arreglo manipulable de JavaScript.

¿Por qué GET no necesita segundo argumento en fetch? Porque por defecto, si no se pasa el objeto de opciones, fetch(url) asume el método GET y sin cuerpo (body).
BLOQUE 1 Manejo Defensivo de Errores
SLIDE 07 / 25

El Objeto `Response`: ¡La Gran Trampa de Fetch!

Atención a este concepto crítico: `fetch()` NO rechaza la promesa cuando el servidor responde con error 404 Not Found o 500 Internal Server Error.

¿Cuándo va fetch() al bloque `catch`?

ÚNICAMENTE ante errores de red catastróficos a nivel de infraestructura:

  • El servidor Express está apagado (ECONNREFUSED).
  • No hay conexión a internet o cable de red desconectado.
  • Error de resolución DNS de la URL.
  • Bloqueo de seguridad por política CORS.
// Si el servidor responde 404 o 500, ¡FETCH CREE QUE FUE UN ÉXITO DE COMUNICACIÓN!
Propiedades Clave del Objeto `Response`
res.ok true si el status está entre 200 y 299. false en caso contrario.
res.status Código numérico HTTP exacto (200, 201, 400, 404, 500).
res.statusText Texto oficial del protocolo ("OK", "Not Found", "Created").
res.headers Cabeceras enviadas por el servidor (res.headers.get('content-type')).
Patrón Defensivo Obligatorio en ADSO: Siempre escribe if (!res.ok) throw new Error(...) justo después del primer await.
BLOQUE 1 Transporte de Datos
SLIDE 08 / 25

Serialización y Deserialización: `JSON.stringify()` vs `res.json()`

El protocolo HTTP solo puede transportar cadenas de texto o bytes a través del cable de red. No puede enviar directamente una referencia de objeto en memoria de JavaScript.

ENVIAR: Objeto JS ➔ String JSON Serialización

Usamos JSON.stringify(objeto) para empaquetar los datos antes de enviarlos en el body de peticiones POST o PATCH:

const nuevoProducto = {
  nombre: "Mouse Ergonómico",
  precio: 95000,
  stock: 12
};

// Convierte a string para poder viajar por HTTP:
const bodyTexto = JSON.stringify(nuevoProducto);
// '{"nombre":"Mouse Ergonómico","precio":95000,"stock":12}'
RECIBIR: String JSON ➔ Objeto JS Deserialización

El método res.json() lee el stream de texto que envía Express y lo reconstruye en un objeto vivo:

const res = await fetch('http://localhost:3000/api/productos');

// Parsea el texto JSON a un objeto/array nativo de JS:
const respuesta = await res.json();

console.log(respuesta.datos[0].nombre); // Acceso a propiedades
console.log(typeof respuesta); // 'object'
Dirección Frontend ➔ Backend: JSON.stringify() + Header 'Content-Type': 'application/json'.
Dirección Backend ➔ Frontend: Servidor usa res.json() y Cliente usa await res.json().

Arquitectura de la SPA: El Estado Local como Fuente de la Verdad

Principio fundamental de ingeniería frontend: El DOM no es la base de datos. El DOM es únicamente la proyección visual de una estructura de datos en memoria llamada Estado.

recursos/cliente.js (Estado Reactivo Frontend) Variables DOM + Estado Central 
// 1. Captura de elementos del HTML por ID (definidos en index.html)
const gridProductos = document.getElementById('grid-productos');
const estadoCarga   = document.getElementById('estado-carga');
const estadoError   = document.getElementById('estado-error');

// 2. Estado reactivo en memoria de la SPA (cliente.js)
let estadoApp = {
  productos: [],             // Catálogo descargado del backend
  categoriaActiva: 'TODAS',  // Filtro seleccionado (TODAS, HARDWARE, etc.)
  terminoBusqueda: '',       // Texto ingresado en el buscador
  conectadoABackend: false   // Bandera de conectividad con Express
};

// 3. Cada vez que cambia el estado, se renderiza la UI:
function aplicarFiltrosYRenderizar() {
  const filtrados = estadoApp.productos.filter(/* condiciones */);
  renderizarCatalogo(filtrados);
}

¿Por qué trabajar con un objeto de Estado?

  • Filtrado instantáneo en memoria: No necesitas volver a consultar el servidor para buscar o filtrar por categoría.
  • Sincronización Predecible: Cuando el backend responde 201 Created o 200 OK, actualizas el array y re-renderizas sin F5.
  • Puente a React (Semana 2): Este patrón es exactamente la antesala del hook useState() que aprenderemos en el Día 14.
El Flujo Unidireccional: Petición Fetch ➔ Actualizar `estadoApp` ➔ Ejecutar `renderizarCatalogo()` ➔ El DOM se actualiza de forma limpia.

  estadoCarga.classList.remove('hidden');
  gridProductos.classList.add('hidden');
  estadoError.classList.add('hidden');

}

function renderizarCatalogo(lista) {
  gridProductos.innerHTML = ''; // Limpiar tarjetas previas

  if (lista.length === 0) {
    estadoVacio.classList.remove('hidden');
    gridProductos.classList.add('hidden');
    return;
  }

  estadoVacio.classList.add('hidden');
  gridProductos.classList.remove('hidden');

  // Mapear cada producto a un string HTML estructurado
  const tarjetasHTML = lista.map(prod => {
    const precioCOP = new Intl.NumberFormat('es-CO', { style: 'currency', currency: 'COP', maximumFractionDigits: 0 }).format(prod.precio);
    const badgeStock = prod.stock > 5 ? 'bg-emerald-50 text-emerald-700 border-emerald-200' :
                       prod.stock > 0 ? 'bg-amber-50 text-amber-700 border-amber-200' :
                       'bg-rose-50 text-rose-700 border-rose-200';

    return `
      <div class="bg-white border border-slate-200 rounded-2xl p-4 shadow-xs hover:shadow-md transition space-y-3">
        <div class="flex items-center justify-between">
          <span class="text-[10px] font-mono px-2 py-0.5 rounded bg-slate-100 text-slate-600 font-bold">${prod.sku}</span>
          <span class="text-[10px] font-mono px-2 py-0.5 rounded border ${badgeStock}">Stock: ${prod.stock}</span>
        </div>
        <h3 class="font-bold text-slate-900 text-sm truncate">${prod.nombre}</h3>
        <div class="text-base font-extrabold text-[#00324D]">${precioCOP}</div>
        <div class="pt-2 border-t border-slate-100 flex items-center justify-between gap-2">
          <button onclick="actualizarStockRapido(${prod.id}, ${prod.stock + 1})" class="text-xs px-2.5 py-1 bg-slate-100 hover:bg-slate-200 rounded-lg font-bold">+1 Stock</button>
          <button onclick="eliminarProductoConfirmado(${prod.id})" class="text-xs text-rose-600 hover:bg-rose-50 p-1.5 rounded-lg">Eliminar</button>
        </div>
      </div>
    `;
  }).join('');

  gridProductos.innerHTML = tarjetasHTML;
}
Estándar Internacional: Intl.NumberFormat('es-CO', { style: 'currency', currency: 'COP' }) formatea el valor 150000 como $ 150.000 automáticamente.

Paso 3: Buscador en Tiempo Real y Filtros por Categoría

Como ya tenemos todo el catálogo en estadoApp.productos, podemos filtrar a la velocidad del procesador local sin saturar el servidor con peticiones GET adicionales.

Instrucción: Filtra con .filter() en memoria y pasa la lista resultante a renderizarCatalogo().
Conexión DOM: Listener de #input-busqueda (evento input) y botones .btn-filtro
Recursos (.ZIP)
recursos/cliente.js · aplicarFiltrosYRenderizar() Lógica de Filtrado Local 
function aplicarFiltrosYRenderizar() {
  const termino = estadoApp.terminoBusqueda.toLowerCase().trim();
  const categoria = estadoApp.categoriaActiva;

  // Filtrado compuesto con Array.prototype.filter():
  const filtrados = estadoApp.productos.filter(prod => {
    // 1. Coincidencia por categoría
    const coincideCategoria = categoria === 'TODAS' || prod.categoria === categoria;

    // 2. Coincidencia por texto en nombre o SKU
    const coincideTexto = !termino ||
      prod.nombre.toLowerCase().includes(termino) ||
      prod.sku.toLowerCase().includes(termino);

    return coincideCategoria && coincideTexto;
  });

  // Actualizar contador visual de resultados
  conteoProductos.textContent = `${filtrados.length} de ${estadoApp.productos.length} productos`;

  // Enviar arreglo filtrado a pintar en el DOM
  renderizarCatalogo(filtrados);
}

Eventos de Entrada del Usuario

input en #input-busqueda:

Se dispara con cada pulsación de tecla sin necesidad de presionar Enter.

click en .btn-filtro:

A través de delegación de eventos en #contenedor-filtros, extrae boton.dataset.categoria.

¿Cuándo filtrar en cliente vs servidor? Si el catálogo tiene cientos de elementos, filtrar en cliente es instantáneo. Si tiene cientos de miles de registros con paginación, el filtrado debe hacerse en backend con req.query.

Formularios HTML5: El Peligro del Recargo y `e.preventDefault()`

Por diseño histórico de los años 90, cuando un formulario HTML se envía (submit), el navegador recarga la página por completo enviando una petición síncrona. En una SPA, esto destruye toda la memoria JavaScript.

Sin e.preventDefault() (Comportamiento Nativo) Página Parpadea / F5
  1. El usuario pulsa el botón <button type="submit">.
  2. El navegador intenta navegar hacia la URL del atributo action="...".
  3. Se descarga el HTML desde cero, perdiendo todas las variables y el estado en memoria (estadoApp se reinicia).
  4. La petición Fetch asíncrona que intentaste disparar se cancela bruscamente.
Con e.preventDefault() (Arquitectura SPA) Fluido y Reactivo
  1. El evento 'submit' es interceptado en la primera línea.
  2. e.preventDefault() frena la recarga del navegador.
  3. Leemos los valores de los inputs con JavaScript en memoria.
  4. Enviamos la petición fetch() asíncronamente en segundo plano.
  5. La página NUNCA parpadea ni recarga; el modal se cierra y la nueva tarjeta aparece al instante.
formProducto.addEventListener('submit', async (e) => { e.preventDefault(); // 🛑 ¡LÍNEA SAGRADA DEL FRONTEND! Cancela el refresh nativo del navegador. console.log("Formulario interceptado con éxito. Ejecutando Fetch en segundo plano..."); });
BLOQUE 2 Extracción y Tipado de Datos
SLIDE 14 / 25

Captura de Datos de Formularios: `new FormData()` vs Selección Directa

Para construir el payload que viajará al backend, debemos leer los campos del formulario. Existen dos aproximaciones principales en JavaScript Vanilla.

Método Moderno: new FormData(form) Usa atributo 'name' 
const formData = new FormData(e.target);

const nuevoProducto = {
  nombre: formData.get('nombre').trim(),
  sku: formData.get('sku').trim().toUpperCase(),
  categoria: formData.get('categoria'),
  precio: Number(formData.get('precio')),
  stock: Number(formData.get('stock'))
};

Ventaja: No requiere buscar cada input por ID. Solo exige que cada campo tenga un atributo name="..." en el HTML.

Método Clásico: Selección por ID Usa getElementById 
const nuevoProducto = {
  nombre: document.getElementById('input-nombre').value.trim(),
  sku: document.getElementById('input-sku').value.trim().toUpperCase(),
  categoria: document.getElementById('select-categoria').value,
  precio: Number(document.getElementById('input-precio').value),
  stock: Number(document.getElementById('input-stock').value)
};

Válido pero verboso: Requiere una variable o query por cada campo. Si el formulario tiene 15 campos, el código se vuelve muy extenso.

¡Cuidado con los tipos! Todo valor extraído de un input HTML es siempre un string (incluso en <input type="number">). Debes convertir explícitamente con Number(valor) para evitar que Express rechace la petición con 400 Bad Request.

async function manejarCreacionProducto(e) {
  e.preventDefault(); // 1. Evitar recarga de página

  // 2. Extraer y estructurar datos del formulario
  const formData = new FormData(formProducto);
  const nuevoProducto = {
    sku: formData.get('sku').trim().toUpperCase(),
    nombre: formData.get('nombre').trim(),
    categoria: formData.get('categoria'),
    precio: Number(formData.get('precio')),
    stock: Number(formData.get('stock'))
  };

  try {
    // 3. Ejecutar fetch() con el objeto de opciones configurado
    const res = await fetch(API_URL, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json' // 🚨 OBLIGATORIO: Informa a express.json()
      },
      body: JSON.stringify(nuevoProducto)  // 🚨 OBLIGATORIO: Texto serializado
    });

    // 4. Validar status (Express responderá 201 Created si tuvo éxito)
    if (!res.ok) {
      const errorData = await res.json();
      throw new Error(errorData.error || 'Error al guardar el producto');
    }

    const resultado = await res.json();
    console.log("Servidor respondió 201:", resultado.mensaje);

    // 5. Flujo de éxito en UI (cerrar modal, resetear formulario y recargar)...
  } catch (error) {
    mostrarToast(error.message, 'error');
  }
}
¿Qué ocurre si olvidas poner 'Content-Type': 'application/json'? El middleware express.json() del servidor ignorará la petición y en el backend req.body llegará como undefined, provocando un error 400 Bad Request.

async function actualizarStockProducto(id, nuevoStock) {
  if (nuevoStock < 0 || isNaN(nuevoStock)) {
    mostrarToast('El stock no puede ser negativo', 'error');
    return;
  }

  try {
    const res = await fetch(`${API_URL}/${id}/stock`, {
      method: 'PATCH',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ nuevoStock: Number(nuevoStock) })
    });

    if (!res.ok) {
      const err = await res.json();
      throw new Error(err.error || 'No se pudo actualizar el stock');
    }

    // Actualización local in-place para máxima velocidad:
    const producto = estadoApp.productos.find(p => p.id === id);
    if (producto) producto.stock = nuevoStock;

    aplicarFiltrosYRenderizar();
    mostrarToast('Stock actualizado correctamente', 'exito');

  } catch (error) {
    mostrarToast(error.message, 'error');
  }
}

Diferencia Semántica: PUT vs PATCH

PUT /api/productos/:id

Reemplazo COMPLETO del recurso. Exige enviar todos los campos (nombre, precio, stock, categoria, sku).

PATCH /api/productos/:id/stock

Modificación PARCIAL. Solo enviamos el campo específico que cambió ({ nuevoStock: 15 }).

Actualización Optimista: Modificar el objeto en memoria antes o inmediatamente después de la confirmación hace que la UI responda a 60 FPS sin recargar el catálogo.

async function eliminarProductoConfirmado(id) {
  // 1. Confirmación de seguridad defensiva
  const confirmar = confirm(`¿Estás seguro de eliminar el producto con ID ${id}?`);
  if (!confirmar) return; // Si cancela, no se envía nada

  try {
    // 2. Enviar petición DELETE a la ruta parametrizada de Express
    const res = await fetch(`${API_URL}/${id}`, {
      method: 'DELETE'
    });

    // 3. Validar respuesta del servidor (Status 200 o 204)
    if (!res.ok) {
      const err = await res.json();
      throw new Error(err.error || 'No se pudo eliminar el producto');
    }

    // 4. Remover del estado local en memoria
    estadoApp.productos = estadoApp.productos.filter(p => p.id !== id);

    // 5. Re-renderizar catálogo y notificar al usuario
    aplicarFiltrosYRenderizar();
    mostrarToast('Producto eliminado exitosamente', 'exito');

  } catch (error) {
    mostrarToast(error.message, 'error');
  }
}

Flujo Seguro de Eliminación

Paso 1: Diálogo modal o nativo confirm().
Paso 2: Petición DELETE /api/productos/:id al servidor.
Paso 3: Filtrado local del array (filter(p => p.id !== id)).
Paso 4: Actualización del contador y Toast informativo.
¡CRUD Completo Dominado! Has conectado las 4 operaciones (Create = POST, Read = GET, Update = PATCH, Delete = DELETE) desde la interfaz de usuario.

function mostrarToast(mensaje, tipo = 'info') {
  const toast = document.createElement('div');
  const estilos = tipo === 'exito' ? 'bg-emerald-800 text-white border-emerald-600' :
                  tipo === 'error' ? 'bg-rose-800 text-white border-rose-600' :
                  'bg-slate-800 text-white border-slate-600';

  toast.className = `px-4 py-2.5 rounded-xl text-xs font-bold shadow-lg border flex items-center gap-2 animate-in fade-in slide-in-from-bottom-2 ${estilos}`;
  toast.innerHTML = `
    <span>${tipo === 'exito' ? '✓' : tipo === 'error' ? '✕' : 'ℹ'}</span>
    <span>${mensaje}</span>
  `;

  toastContainer.appendChild(toast);

  // Destrucción automática tras 3.5 segundos:
  setTimeout(() => {
    toast.remove();
  }, 3500);
}

Los 4 Estados de Toda Vista Web

1. Loading: Spinner mientras fetch() viaja.
2. Success: Catálogo con las tarjetas inyectadas.
3. Empty: "No se encontraron productos" en la búsqueda.
4. Error: Banner rojo con botón "Reintentar conexión".
Empatía con el Usuario: El software nunca debe dejar al usuario adivinando si algo falló o funcionó. Toda acción tiene una reacción visual en la pantalla.
