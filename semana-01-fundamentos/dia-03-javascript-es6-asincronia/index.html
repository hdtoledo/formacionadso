El Runtime de Node.js: V8 Engine & libuv

JavaScript nació para el navegador, pero Node.js lo llevó al servidor gracias a dos componentes fundamentales: el motor compilador V8 y la biblioteca libuv para operaciones de entrada/salida no bloqueantes.

Motor V8 (Google)

Compila JavaScript directamente a código máquina nativo. Gestiona la memoria (Heap) y la pila de ejecución (Call Stack) donde corre tu lógica de manera secuencial en un solo hilo.

libuv (C/C++)

Biblioteca multiplataforma que provee el Event Loop y administra un grupo de hilos de fondo (Thread Pool) para I/O asíncrono: archivos, sockets y red.

Single Thread & Non-Blocking

Tu código se ejecuta en un único hilo principal, pero las tareas pesadas (consultas a base de datos, lectura de disco) se delegan al sistema operativo sin detener las peticiones entrantes.

En el backend ADSO jamás bloquearemos el hilo principal con bucles síncronos pesados o llamadas I/O síncronas (`fs.readFileSync`).

Alcance y Declaración: const vs let vs el Peligro de var

En el desarrollo backend con JavaScript moderno, la palabra reservada var está estrictamente desaconsejada debido al hoisting y a su alcance de función que provoca fugas de variables.

Reglas de Oro en ADSO

  • 1. Por defecto, siempre usa const: Garantiza que el identificador no será reasignado por accidente.
  • 2. Usa let únicamente si el valor mutará: Contadores de iteración, acumuladores dinámicos o reasignaciones condicionadas.
  • 3. Jamás uses var: Presenta *hoisting* con valor `undefined` y no respeta bloques (`if`, `for`).

Temporal Dead Zone (TDZ)

A diferencia de var, las variables declaradas con let y const existen en la TDZ desde el inicio del bloque hasta su declaración. Intentar usarlas antes genera un ReferenceError inmediato, atrapando errores temprano.

scope_demo.js ES6 Strict 
// ❌ Peligro con 'var' (alcance de función y fugas):
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var:', i), 100);
}
// Imprime: 3, 3, 3 (la variable 'i' se comparte globalmente)

// ✅ Alcance de bloque con 'let' (crea un contexto por iteración):
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log('let:', j), 100);
}
// Imprime correctamente: 0, 1, 2

// ✅ Inmutabilidad de enlace con 'const':
const PORT = 3000;
// PORT = 8080; // ❌ TypeError: Assignment to constant variable.
Resultado en Node.js Node.js Call Stack

SLIDE 04 / 15

Inmutabilidad: Referencia vs Contenido

Uno de los errores conceptuales más frecuentes en aprendices de software es creer que declarar un objeto o array con const vuelve inmutables sus propiedades internas.

¿Qué congela realmente const?

const protege el puntero de memoria (referencia). Impide reasignar la variable a otro objeto, pero permite modificar, agregar o eliminar sus propiedades internas.

Efecto Secundario en Backend:

Si pasas un objeto como parámetro a una función y ésta muta una propiedad, ese cambio afectará a todas las demás partes del sistema que compartan esa misma referencia de memoria.

Patrón Inmutable: Copiar en lugar de Mutar

En arquitecturas limpias de backend (Express, Nest, servicios), siempre generamos un nuevo objeto con los cambios aplicados utilizando el operador spread (...) o structuredClone().

immutability_demo.js JavaScript Heap 
const usuario = {
  id: 101,
  nombre: 'Carlos Pérez',
  activo: true
};

// ✅ Esto es completamente válido (muta el contenido):
usuario.activo = false; 

// ❌ Esto lanzará TypeError (intenta cambiar la referencia):
// usuario = { id: 102 }; // TypeError: Assignment to constant variable

// 🛡️ Enfoque Inmutable Recomendado (Copia con Spread):
const usuarioActualizado = {
  ...usuario,
  rol: 'INSTRUCTOR',
  actualizadoEn: new Date().toISOString()
};

// 🔒 Congelar objeto superficialmente:
Object.freeze(usuarioActualizado);
// usuarioActualizado.rol = 'ADMIN'; // Falla en modo estricto
Heap Allocation Sin efectos secundarios

Desestructuración: Objetos y Arrays

Permite extraer datos de arreglos o propiedades de objetos directamente en variables con una sintaxis limpia, eliminando el código repetitivo como const email = req.body.email;.

Capacidades Clave de ES6+:

  • Alias Renombrar propiedades para evitar colisiones: const { nombre: nombreCliente } = cliente;
  • Default Asignar valores por defecto si la clave es undefined: const { rol = 'INVITADO' } = user;
  • Params Desestructurar directamente en la firma de funciones y controladores Express.
Desestructuración de Arrays (Posicional):

Extrae por posición exacta: const [primerItem, segundoItem, ...resto] = arreglo;

// Objeto simulando petición HTTP o registro de BD:
const pedido = {

const {
  id: pedidoId,

  total,
  descuento = 0
} = pedido;

console.log(`${nombre} de ${ciudad} debe: $${total}`);

// ✅ Desestructuración directa en parámetros de función:

SLIDE 06 / 15

Operador ... : Spread vs Rest

Los tres puntos consecutivos tienen dos propósitos totalmente opuestos dependiendo del contexto: desempaquetar elementos existentes (Spread) o empaquetar múltiples elementos en un arreglo (Rest).

1. Spread Operator (Expandir / Esparcir)

Toma una colección y esparce sus elementos individuales dentro de otro array u objeto. Permite clonar o combinar datos sin mutar los originales: 

const nums = [1, 2, 3];
const copia = [...nums, 4, 5]; // [1, 2, 3, 4, 5]
2. Rest Parameters (Empaquetar / Agrupar)

Agrupa el resto de los argumentos sobrantes dentro de un arreglo. Se usa en firmas de funciones o en desestructuración: 

function sumar(...valores) {
  return valores.reduce((acc, n) => acc + n, 0);
}
spread_rest_usecase.js Modern Patterns 
// Caso Backend: Sanitizar contraseña antes de responder al cliente:
const usuarioDB = {
  id: 105,
  email: 'aprendiz@sena.edu.co',
  passwordHash: '$2b$10$X9...', // ⚠️ Confidencial
  rol: 'APRENDIZ',
  activo: true
};

// ✅ Con Rest podemos omitir claves sensibles limpiamente:
const { passwordHash, ...usuarioPublico } = usuarioDB;

console.log(usuarioPublico);
// { id: 105, email: 'aprendiz@sena.edu.co', rol: 'APRENDIZ', activo: true }

// ✅ Combinar configuraciones de base de datos con Spread:
const configBase = { host: 'localhost', port: 3306, dialect: 'mysql' };
const configProd = { ...configBase, host: 'db.produccion.sena.edu.co' };

Métodos de Arrays I: map(), filter() y find()

Reemplazamos los bucles imperativos for y while por métodos funcionales declarativos que no mutan el array original y devuelven colecciones procesadas.

.map() Transformación 1 a 1

Devuelve un nuevo array con la misma longitud que el original, donde cada elemento es el resultado de aplicarle la función callback. 

const precios = [100, 200];
const conIva = precios.map(p => p * 1.19);
// [119, 238]
.filter() Subconjunto condicional

Devuelve un nuevo array con todos los elementos que cumplan la condición booleana (retornen true en el callback). 

const stock = [15, 0, 8, 0, 4];
const disponibles = stock.filter(s => s > 0);
// [15, 8, 4]
.find() Búsqueda unitaria

Devuelve el primer elemento que coincida con la condición, o undefined si ninguno cumple. Se detiene tan pronto lo encuentra. 

const usuarios = [{ id: 1 }, { id: 2 }];
const u2 = usuarios.find(u => u.id === 2);
// { id: 2 }
Patrón encadenado: pedidos.filter(p => p.activo).map(p => p.total) es legible, mantenible y testeable. Method Chaining

SLIDE 08 / 15

Métodos de Arrays II: reduce(), some() y every()

reduce() es el método funcional más poderoso de JavaScript: puede transformar un array completo en un único número, un objeto agrupado o un mapa de índices.

Anatomía de Array.prototype.reduce()

Recibe dos argumentos: la función reductora (acumulador, elementoActual, index, array) y el valor inicial del acumulador.

⚠️ Regla de Oro: Siempre proporciona el valor inicial (e.g. 0, {} o []). Omitirlo sobre un array vacío lanza un TypeError crítico.
.some() (Existencial)

Retorna true si al menos un elemento cumple la condición.

.every() (Universal)

Retorna true únicamente si todos los elementos cumplen.

reduce_examples.js Array Reduction 
const items = [
  { producto: 'Teclado', precio: 120000, categoria: 'HARDWARE' },
  { producto: 'Mouse', precio: 80000, categoria: 'HARDWARE' },
  { producto: 'Curso ADSO', precio: 0, categoria: 'EDUCACION' }
];

// 1. Calcular el total acumulado:
const totalInventario = items.reduce((acc, item) => acc + item.precio, 0);
console.log('Total:', totalInventario); // 200000

// 2. Agrupar dinámicamente por categoría en un solo paso:
const agrupados = items.reduce((acc, item) => {
  const cat = item.categoria;
  if (!acc[cat]) acc[cat] = [];
  acc[cat].push(item);
  return acc;
}, {});

// 3. Verificaciones de negocio:
const hayGratis = items.some(i => i.precio === 0); // true
const todosHardware = items.every(i => i.categoria === 'HARDWARE'); // false

SLIDE 09 / 15

El Event Loop: Call Stack, libuv y Colas de Tareas

¿Cómo atiende Node.js miles de solicitudes concurrentes con un solo hilo? A través de su bucle de eventos que orquesta la ejecución entre la pila principal y las colas asíncronas.

1 Call Stack (Pila V8)

Donde se apilan las funciones síncronas en ejecución (LIFO: Last In, First Out). Si una función tarda demasiado aquí, bloquea toda la aplicación.

2 Node APIs & libuv

Cuando el código invoca un temporizador, una consulta SQL o una lectura de archivo, el Call Stack delega la operación a libuv y sigue ejecutando la siguiente línea.

3 Microtask Queue

Prioridad Máxima: Contiene callbacks de Promesas resueltas (.then(), await) y process.nextTick. Se vacía antes de cualquier otra cola.

4 Macrotask Queue

Contiene temporizadores (setTimeout, setInterval) y eventos de I/O. El Event Loop pasa sus callbacks al Call Stack cuando la pila está vacía.

Orden de prioridad de ejecución: Código Síncrono (Call Stack) ➔ Microtasks (Promises) ➔ Macrotasks (setTimeout / I/O)
Non-Blocking I/O

SLIDE 10 / 15

Anatomía de una Promise: Estados y Consumo

Una Promesa representa un valor que puede estar disponible ahora, en el futuro o nunca. Reemplaza el antiguo y caótico infierno de callbacks anidados (Callback Hell).

Los 3 Estados Inmutables de una Promesa:

1. Pending (Pendiente) Operación en curso, resultado aún no resuelto
2. Fulfilled (Cumplida) Operación exitosa; dispara resolve(valor)
3. Rejected (Rechazada) Ocurrió un error; dispara reject(error)
Regla de Inmutabilidad de Estado:

Una vez que una promesa pasa a Fulfilled o Rejected, queda fijada para siempre y no puede cambiar de estado ni emitir múltiples valores.

promise_creation.js ES6 Promise 
// Función constructora que simula consulta a BD:
function consultarStock(idProducto) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (idProducto <= 0) {
        reject(new Error('ID de producto inválido'));
      } else {
        resolve({ id: idProducto, stock: 45, bodega: 'Garzón' });
      }
    }, 500);
  });
}

// Consumo tradicional con .then(), .catch() y .finally():
consultarStock(10)
  .then(resultado => {
    console.log('Stock disponible:', resultado.stock);
  })
  .catch(error => {
    console.error('Error al consultar:', error.message);
  })
  .finally(() => {
    console.log('Conexión con base de datos cerrada.');
  });
Encapsulamiento Asíncrono then / catch / finally
Siempre maneja el rechazo con .catch() para evitar la advertencia UnhandledPromiseRejection en Node.js. Safe Handling

SLIDE 11 / 15

Asincronía Lineal: async / await

Introducido en ES2017, async/await permite escribir código asíncrono que se lee y estructura exactamente igual que el código síncrono tradicional, reduciendo drásticamente la carga cognitiva.

Dos Reglas Universales:

  • async Al anteponer async a una función, ésta pasa a devolver automáticamente una Promesa, incluso si retorna un valor primitivo.
  • await Pausa la ejecución de la función async hasta que la promesa se resuelva, sin bloquear en ningún momento el hilo principal de Node.js.
El Error Clásico: Olvidar el `await`

Si olvidas await, la variable no recibirá el dato procesado sino el objeto Promise { <pending> }, causando errores posteriores inesperados.

async_await_flow.js ES2017 Syntax 
// Controlador asíncrono limpio de backend:
async function procesarPedidoCliente(idCliente, productos) {
  console.log('1. Iniciando verificación de cliente...');
  
  // Espera síncrona visual, no bloqueante real:
  const cliente = await buscarClienteDB(idCliente);
  
  console.log(`2. Cliente verificado: ${cliente.nombre}`);
  
  // Segundo paso dependiente del primero:
  const factura = await emitirFacturaDB(cliente.id, productos);
  
  console.log(`3. Factura generada con éxito: #${factura.numero}`);
  return { status: 'OK', factura };
}

// Ejecución limpia:
const respuesta = await procesarPedidoCliente(42, ['Laptop', 'Mouse']);

BLOQUE 1 Control de Fallos Defensivo
SLIDE 12 / 15

Manejo de Errores: try...catch...finally

En un servidor de producción, un error asíncrono no capturado derriba el proceso Node.js completo. El patrón defensivo con bloques try...catch garantiza alta disponibilidad y respuestas estructuradas al cliente.

Estructura del Bloque Defensivo:

  • try: Bloque protegido donde ocurren operaciones que pueden fallar (conexión a base de datos, parseo de JSON, llamadas HTTP).
  • catch (error): Se activa de inmediato si se produce una excepción o si una promesa rechaza con await.
  • finally: Se ejecuta siempre, tanto si hubo éxito como si ocurrió un error. Ideal para liberar conexiones, cerrar archivos o detener temporizadores.
Buenas Prácticas en Backend SENA:

Nunca dejes un bloque catch vacío. Siempre registra el error en consola o sistema de logs (console.error) y retorna un código de error comprensible.

defensive_try_catch.js Robust Backend 
async function registrarVentaSegura(datosVenta) {
  let conexion = null;
  try {
    conexion = await poolConexiones.obtenerConexion();
    console.log('Conexión adquirida...');

    if (!datosVenta.clienteId) {
      throw new Error('El campo clienteId es obligatorio.');
    }

    const resultado = await conexion.insertarVenta(datosVenta);
    return { ok: true, idVenta: resultado.insertId };

  } catch (err) {
    // 🛡️ Registro defensivo del incidente:
    console.error(`[ERROR VENTA] ${err.name}: ${err.message}`);
    return { ok: false, error: err.message };

  } finally {
    // 🧹 Limpieza garantizada de recursos:
    if (conexion) {
      await conexion.liberar();
      console.log('Conexión devuelta al pool correctamente.');
    }
  }
}

SLIDE 13 / 15

Concurrencia: Promise.all() vs Promise.allSettled()

Un error grave de rendimiento en backend es ejecutar consultas independientes en serie con múltiples await sucesivos, multiplicando el tiempo total de respuesta.

❌ Secuencial Lento (300ms + 300ms + 300ms = 900ms) 
// Ineficiente si las consultas son independientes:
const usuarios = await db.obtenerUsuarios();   // 300ms
const pedidos = await db.obtenerPedidos();     // 300ms
const categorias = await db.obtenerCategorias(); // 300ms
// Tiempo total consumido: 900ms 🐌
✅ Concurrente en Paralelo (Total: 300ms) 
// Dispara las 3 al mismo tiempo y espera el paquete:
const [usuarios, pedidos, categorias] = await Promise.all([
  db.obtenerUsuarios(),
  db.obtenerPedidos(),
  db.obtenerCategorias()
]);
// Tiempo total consumido: 300ms ⚡ (3 veces más rápido)

¿Cuándo usar cada combinador?

Promise.all() [Todo o Nada]

Falla de inmediato (fail-fast) si cualquiera de las promesas es rechazada. Se usa cuando todas las operaciones son estrictamente indispensables para continuar.

Promise.allSettled() [Auditoría Completa]

Espera a que todas terminen, sin importar si triunfaron o fallaron. Devuelve un array de objetos con estado { status: 'fulfilled', value } o { status: 'rejected', reason }. Ideal para envíos masivos de emails o sincronizaciones.

Optimización directa de latencia: Siempre identifica operaciones I/O independientes y ejecútalas en paralelo. Latency Optimization
