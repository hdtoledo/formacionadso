BLOQUE 1 Evolución del CSS en la Industria
SLIDE 02 / 32

De CSS Tradicional a Utility-First: El Cambio de Paradigma

Históricamente, los desarrolladores escribían archivos styles.css kilométricos inventando nombres de clases arbitrarios (.btn-primary-card-wrapper). Tailwind CSS propone componer diseños directamente en el HTML usando **clases utilitarias atómicas**.

CSS Tradicional / Metodología BEM Lento y Frágil 
/* styles.css crece sin control hasta miles de líneas */
.tarjeta-usuario {
  background-color: #ffffff;
  border-radius: 16px;
  padding: 24px;
  box-shadow: 0 4px 6px rgba(0,0,0,0.1);
}
.tarjeta-usuario__boton--activo {
  background-color: #39A900;
  color: white;
  padding: 8px 16px;
}

Problemas: "Miedo a borrar CSS", nombres inventados, archivos pesados y especificidad descontrolada.

Tailwind CSS (Utility-First) Rápido y Escalable 
<!-- Clases atómicas universales directamente en el markup -->
<div class="bg-white rounded-2xl p-6 shadow-md">
  <h3 class="text-lg font-bold text-slate-900">Carlos Gómez</h3>
  <button class="bg-[#39A900] hover:bg-[#2D8200] text-white px-4 py-2 rounded-xl text-xs font-bold transition">
    Ver Perfil
  </button>
</div>

Ventajas: Sin inventar nombres, tamaño final minúsculo, consistencia total y fácil mantenimiento.

Regla de Oro: En Tailwind no inventas nombres de clases; compones la interfaz usando un vocabulario visual estandarizado.

¿Cómo Funciona Tailwind? Motor JIT (Just-in-Time) y Purge

A diferencia de Bootstrap (que descarga un archivo CSS gigantesco con miles de estilos que jamás usarás), Tailwind utiliza un **motor JIT** que escanea tu código HTML y genera **únicamente** el CSS que realmente estás utilizando.

1

Escaneo de Archivos

El compilador lee tus archivos (.html, .jsx, .vue) buscando cadenas de texto con nombres de clases utilitarias.

2

Generación On-Demand

Si escribes p-4 o un valor arbitrario w-[312px], Tailwind genera el CSS exacto en ese milisegundo en memoria.

3

Bundle Mínimo (< 15 KB)

En producción, todo el CSS no utilizado se descarta por completo. Tu sitio web carga a velocidad instantánea en cualquier conexión móvil.

⚡ En producción, un sitio web gigante con Tailwind suele pesar menos de 12 KB comprimido (gzip). Ultra Optimizado

Métodos de Integración: Play CDN vs. Tailwind CLI / Vite

Para prototipado rápido en aula utilizamos el Play CDN oficial (sin compiladores pesados). En la Semana 2, cuando integremos React y Vite, usaremos el pipeline de compilación profesional:

Método 1: Play CDN (El que usaremos hoy) Cero Config 
<!-- En el <head> de tu archivo HTML -->
<script src="https://cdn.tailwindcss.com"></script>

<!-- Opcional: Personalizar tema en línea -->
<script>
  tailwind.config = {
    theme: {
      extend: {
        colors: { 'sena-green': '#39A900' }
      }
    }
  }
</script>

Perfecto para aprender, realizar talleres en clase y abrir con Live Server sin Node.js.

Método 2: Tailwind CLI / Vite (Semana 2) Industrial 
# 1. Instalar dependencias en el proyecto
npm install -D tailwindcss postcss autoprefixer

# 2. Inicializar archivo de configuración
npx tailwindcss init -p

# 3. Compilar en vivo
npx tailwindcss -i ./src/input.css -o ./dist/output.css --watch

Lo utilizaremos en proyectos de React, Next.js o cuando el bundler optimice para producción.

💡 El script de Play CDN compila en tiempo real dentro del propio navegador. ¡Ideal para el taller de hoy!
BLOQUE 1 Identidad de Marca & Tokens
SLIDE 05 / 32

Personalización del Tema: Objeto tailwind.config

No tienes que limitarte a los colores por defecto. Con theme.extend puedes inyectar los colores institucionales del SENA, tipografías y sombras personalizadas:

Script en el <head> de tus vistas Tokens Oficiales 
tailwind.config = {
  theme: {
    extend: {
      colors: {
        sena: {
          green: '#39A900',        // bg-sena-green, text-sena-green
          'green-dark': '#2D8200', // hover:bg-sena-green-dark
          navy: '#00324D',         // bg-sena-navy
          'navy-dark': '#00263A'
        }
      },
      fontFamily: {
        sans: ['Plus Jakarta Sans', 'sans-serif'],
        mono: ['JetBrains Mono', 'monospace']
      }
    }
  }
}

Clases Creadas Automáticamente:

bg-sena-green
bg-sena-navy
font-sans Plus Jakarta Sans
🎨 Al extender el tema, Tailwind mantiene intacta toda su paleta nativa (slate, emerald, blue, rose).

Principios de UI (Interfaz) vs. UX (Experiencia)

Un software no es profesional si es difícil de usar o visualmente caótico. Como tecnólogos ADSO, debemos dominar la dualidad entre cómo se ve y cómo se siente la aplicación:

UI

User Interface (Lo que el usuario ve)

  • Tipografía: Legibilidad, tamaños armónicos y pesos claros.
  • Color y Estética: Paletas armoniosas, sombras y bordes redondeados.
  • Consistencia: Todos los botones primarios tienen la misma forma y color.
  • Iconografía: Metáforas universales (correo = sobre, buscar = lupa).
UX

User Experience (Lo que el usuario siente)

  • Fricción Cero: Formularios simples con pocos campos requeridos.
  • Feedback Inmediato: Spinners mientras carga y mensajes de éxito claros.
  • Accesibilidad: Textos con alto contraste para personas con debilidad visual.
  • Ley de Fitts: Los botones importantes son grandes y fáciles de tocar en móvil.
Conclusión: La UI atrae al usuario por los ojos; la UX hace que el usuario logre su objetivo sin frustrarse.
BLOQUE 1 Regla UI #1: Tipografía
SLIDE 07 / 32

Jerarquía Visual: El Ojo del Usuario No Lee Todo, Escanea

Si todos los textos de tu pantalla tienen el mismo tamaño y peso, el usuario experimenta fatiga visual y se pierde. Con Tailwind aplicamos **3 niveles de escala tipográfica**:

Nivel 1: Títulos (H1 / H2)

Título Dominante

text-2xl sm:text-4xl font-black

Captura la atención primaria en menos de 0.5 segundos.

Nivel 2: Subtítulos y Labels

Etiquetas y Secciones Clave

text-sm font-extrabold text-slate-800

Guía al usuario hacia las acciones y campos del formulario.

Nivel 3: Textos Secundarios

Descripciones de apoyo, placeholders y metadatos.

text-xs font-normal text-slate-500

No compite con el título principal; ofrece contexto.

💡 Consejo Pro: Nunca uses más de 2 familias tipográficas en un proyecto (una Sans para lectura y una Mono para código o cifras).
BLOQUE 1 Regla UI #2: Espaciado
SLIDE 08 / 32

Espaciado Armónico: La Regla Sagrada de los 4 Píxeles

El diseño amateur se reconoce porque usa medidas aleatorias (13px, 19px, 37px). Los sistemas de diseño profesionales (Google Material, Apple HIG) se basan estrictamente en **múltiplos de 4px**:

Clase Tailwind Píxeles Uso Recomendado en UI/UX Muestra Visual
p-1 / m-1 / gap-1 4 px Micro-espaciados (badges, chips internos).
p-2 / m-2 / gap-2 8 px Distancia entre icono y texto en botones.
p-4 / m-4 / gap-4 16 px Padding estándar de tarjetas y gap de grillas.
p-6 / m-6 / gap-6 24 px Separación entre bloques mayores y contenedores.
p-8 / m-8 / space-y-8 32 px Padding de modales amplios y secciones.
📐 Ley de Proximidad: Elementos relacionados van juntos (gap-1.5 entre label e input); secciones distintas van separadas (space-y-6).
BLOQUE 1 Regla UI #3: Color & Accesibilidad
SLIDE 09 / 32

Teoría del Color y Accesibilidad: Contraste WCAG 2.1

Los colores en una interfaz transmiten significado de forma instantánea. Un software profesional usa una paleta semántica estricta:

Éxito / Acción

bg-emerald-600

Botones primarios, confirmaciones y estados completados.

Institucional / Info

bg-[#00324D]

Cabeceras institucionales, enlaces neutrales e información.

Alerta / Warning

bg-amber-500

Advertencias de stock bajo, conflictos y cambios irreversibles.

Peligro / Destructivo

bg-rose-600

Errores 404/500, borrado con DELETE y validaciones fallidas.

Regla de Accesibilidad: Nunca uses texto gris claro sobre fondo blanco. Usa text-slate-600 o text-slate-800 para cumplir el ratio de contraste mínimo 4.5:1 (WCAG AA).
BLOQUE 1 Regla UI #4: Estados Interactivos
SLIDE 10 / 32

Micro-interacciones: Los 6 Estados Obligatorios de Todo Control

En una interfaz moderna, ningún botón o input es estático. Todo elemento debe responder al usuario en cada interacción:

1. Normal bg-emerald-600
2. Hover (Cursor) hover:bg-emerald-700
3. Active (Clic) active:scale-95
4. Focus (Teclado) focus:ring-4
5. Disabled disabled:opacity-50
6. Group Hover
Card →
group-hover:text-...
✨ Combina siempre con transition-all duration-200 para que el cambio no sea brusco sino fluido.
BLOQUE 1 Iconografía SVG
SLIDE 11 / 32

Iconografía Moderna: Integración de Lucide Icons

Los iconos reducen la carga cognitiva y guían la navegación. En lugar de imágenes pesadas PNG, usamos **Lucide Icons** (vectorial, ligero y estilizable con Tailwind):

Cómo usar Lucide Icons con CDN Librería Ligera 
<!-- 1. Cargar script en el <head> -->
<script src="https://unpkg.com/lucide@latest"></script>

<!-- 2. Insertar etiquetas con el atributo data-lucide -->
<button class="inline-flex items-center gap-2 bg-[#39A900] text-white px-4 py-2.5 rounded-xl font-bold text-xs">
  <i data-lucide="mail" class="w-4 h-4"></i>
  <span>Enviar Correo</span>
</button>

<!-- 3. Inicializar al final del <body> -->
<script>lucide.createIcons();</script>

Regla de Alineación Icono + Texto:

Usa siempre inline-flex items-center gap-2. Esto evita que el icono quede desalineado o subido respecto al texto:

Alineación Perfecta items-center

BLOQUE 2 Diseño Adaptativo
SLIDE 12 / 32

Arquitectura Mobile-First y Breakpoints

En Tailwind, **las clases sin prefijo aplican primero a pantallas móviles**. Solo cuando la pantalla supera un breakpoint determinado, se activan los prefijos responsivos:

sm:

640 px

Móviles horizontales y tablets pequeñas.

md:

768 px

Tablets estándar (iPad) en vertical.

lg:

1024 px

Laptops y pantallas de escritorio.

xl:

1280 px

Monitores Full HD de aula.

2xl:

1536 px

Pantallas Ultra-Wide y 4K.

<!-- En móvil es 1 columna; a partir de tablet (md) se convierte en 3 columnas --> <div class="grid grid-cols-1 md:grid-cols-3 gap-4"> ... </div>
📱 Regla: Diseña primero cómo se verá en un celular, luego añade md: y lg: para expandir.

Componentes V: Navbar con Efecto Glassmorphism

Las barras de navegación fijas modernas usan backdrop-blur-md bg-white/90 para crear el efecto de "vidrio esmerilado" que deja entrever el contenido que pasa por debajo:

BLOQUE 2 Micro-Animaciones
SLIDE 20 / 32

Transiciones Suaves: El Toque "Mágico" que Da Vida a la Web

Sin transiciones, los cambios en hover ocurren de forma seca e instantánea (0ms). Al agregar la directiva transition-all duration-300, el navegador interpola suavemente los frames:

Escalado Suave

Pasa el cursor por encima para ver cómo crece suavemente.

hover:scale-105 duration-300

Elevación Vertical

La tarjeta parece levitar 8 píxeles hacia arriba.

hover:-translate-y-2 duration-300

Rotación Sutil

Rotación angular de 2 grados para añadir dinamismo.

hover:rotate-2 duration-300
⏱️ Duración Recomendada: Entre duration-200 y duration-300. Menos es imperceptible; más de 500ms se siente lento y pesado.

animate-spin

Para spinners de carga durante peticiones fetch().

animate-pulse

BLOQUE 2 Calidad de Código
SLIDE 22 / 32

Buenas Prácticas vs. Antipatrones en Tailwind

Escribir clases utilitarias no significa escribir desorden. Sigue estas 4 reglas para mantener un código limpio y legible:

Prácticas Recomendadas

  • Orden Lógico de Clases: Layout → Espaciado → Tipografía → Colores → Efectos (flex items-center p-4 text-sm bg-white shadow).
  • Mobile-First Estricto: Pon siempre el estilo móvil primero y luego las variantes md:.
  • Componentes Reutilizables: Cuando un botón se repite 10 veces, es señal de que en React será un componente <Button />.

Antipatrones a Evitar

  • Abuso de Valores Arbitrarios: No abuses de w-[317px] o p-[19px]; respeta la escala de 4px (w-80, p-5).
  • Olvidar focus-visible: Todo botón interactivo debe poder seleccionarse con la tecla Tab del teclado.
  • Uso de !important: En Tailwind casi nunca necesitas !p-4 si la jerarquía está bien construida.
