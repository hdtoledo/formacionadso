Bloque 1 · Arquitectura

¿Por qué Mongoose si la colección ya tiene validator?

Validator de la Sesión 07 (en MongoDB)
  • Configurado con validationAction: "warn": registra, pero no bloquea.
  • Solo exige type, active y las fechas.
  • Sus errores no tienen mensajes para el usuario.
Esquema Mongoose (en la aplicación)
  • Reglas por tipo: obligatorios, longitudes, enums y formatos de URL.
  • Mensajes en español que llegan al frontend como fieldErrors.
  • timestamps, valores por defecto y strict (descarta campos desconocidos).
Son complementarios: el esquema de Mongoose protege lo que entra por la API; el validator de MongoDB es la red de seguridad para quien escriba directo en Compass o mongosh.

import mongoose from 'mongoose';
import { config } from '../config/environment.js';

const { Schema } = mongoose;

export const CONTENT_TYPES = ['banner', 'service', 'testimonial', 'stat', 'event'];
export const CONTENT_CATEGORIES = ['software', 'agroindustria', 'seguridad', 'innovacion'];

// Solo https://... o rutas internas que empiecen por "/".
// Bloquea enlaces "javascript:alert(1)", que en un <a href> del frontend serían XSS,
// y "//otro-dominio.com" (empieza por "/" pero el navegador lo trata como dominio externo).
const HTTPS_URL = /^https:\/\/\S+$/;
const SAFE_LINK = /^(https:\/\/\S+|\/(?!\/)[\w\-./]*)$/;

// -----------------------------------------------------------------------------
// 1. Esquema base: lo que comparten TODOS los contenidos
// -----------------------------------------------------------------------------
const ContentSchema = new Schema(
  {
    // true = publicado en la Landing · false = borrador (por defecto, nada se publica solo)
    active: { type: Boolean, default: false },
    tags: {
      type: [{ type: String, trim: true, lowercase: true, maxlength: [30, 'Cada etiqueta admite máximo 30 caracteres.'] }],
      default: undefined,
      validate: { validator: (tags) => tags.length <= 10, message: 'Máximo 10 etiquetas por contenido.' }
    }
  },
  {
    discriminatorKey: 'type',   // El campo que distingue banner, service, testimonial...
    collection: 'contents',     // La misma colección creada en la Sesión 07
    timestamps: true,           // createdAt y updatedAt automáticos
    strict: true,               // Campos no declarados en el esquema se descartan
    autoIndex: !config.isProduction // En producción los índices se crean con scripts, no al arrancar
  }
);

// Índices: mismos nombres y opciones que el script 01_adso_polyglot_setup.js (Sesión 07).
// Si los nombres no coincidieran, MongoDB rechazaría el índice "duplicado".
ContentSchema.index({ active: 1, priority: 1 }, { name: 'idx_active_priority' });
ContentSchema.index({ type: 1, active: 1 }, { name: 'idx_type_active' });
ContentSchema.index({ code: 1 }, { unique: true, sparse: true, name: 'idx_unique_service_code' });
ContentSchema.index({ category: 1 }, { sparse: true, name: 'idx_category' });
ContentSchema.index(
  { title: 'text', name: 'text', tags: 'text', description: 'text' },
  { name: 'idx_fulltext_search', default_language: 'spanish' }
);

export const Content = mongoose.model('Content', ContentSchema);
active: false por defectoNada se publica por accidente: si el cliente no envía active, el contenido nace como borrador.
Mismos nombres de índiceSi Mongoose declarara {active, priority} con otro nombre, MongoDB respondería "Index already exists with a different name".
autoIndex en producción: falseCrear índices al arrancar bloquea colecciones grandes; en producción se crean con scripts controlados.
¿Y el campo type? No se declara: discriminatorKey: 'type' lo agrega y lo llena Mongoose según el discriminator.

Bloque 1 · OWASP Top 10: A03 Injection (versión NoSQL)

"MongoDB no usa SQL, entonces no hay inyección"… falso

❌ Código vulnerable 
// El valor de la URL va directo al filtro
const data = await Content.find({
  active: true,
  type: req.query.type
});

El atacante pide: /api/content/published?type[$ne]=banner

req.query.type === { $ne: 'banner' } // ¡un objeto, no un texto!
1. Express interpreta los corchetesLa sintaxis a[b]=c de la query string se convierte en el objeto { a: { b: 'c' } }.
2. $ne es un operador de MongoDBEl filtro deja de ser "tipo igual a…" y pasa a ser "tipo distinto de banner".
3. El atacante controla la consultaCon $gt, $regex o $where puede saltarse filtros, como el de active en un login o en un recurso privado.
Resultado medido: sin protección, el filtro { type: { $ne: 'banner' } } devolvió los 8 documentos que no son banners.

Defensa en dos capas

Capa 1 · Controlador: tipo y lista blanca 
// El tipo debe ser TEXTO y estar en la lista blanca.
// ?type[$ne]=banner llega como objeto { $ne: 'banner' }: sin esta validación sería inyección NoSQL.
const assertContentType = (type) => {
  if (typeof type !== 'string' || !CONTENT_TYPES.includes(type)) {
    throw new AppError(400, 'VALIDATION_ERROR', 'Los datos enviados no son válidos.', {
      type: `Debe ser uno de: ${CONTENT_TYPES.join(', ')}.`
    });
  }

Capa 2 · config/db.js: red de seguridad global 
// Defensa contra inyección NoSQL (Sesión 10), segunda capa tras validar en el controlador:
// - sanitizeFilter: si un filtro trae un objeto con operadores ($ne, $gt...) donde se
//   esperaba un valor, Mongoose lo envuelve en $eq: deja de ser operador y, como no es
//   texto, la consulta falla con CastError (400) en lugar de devolver datos ajenos.
// - strictQuery: los filtros por campos que no existen en el esquema se descartan.
mongoose.set('sanitizeFilter', true);
mongoose.set('strictQuery', true);
Medido: con sanitizeFilter, el mismo filtro malicioso termina en CastError (400) y no devuelve ningún documento.

import { STATUS_CODES } from 'node:http';

/**
 * Error de aplicación con código HTTP y código de negocio.
 * Ejemplo (Sesión 09): throw new AppError(409, 'EMAIL_ALREADY_EXISTS', 'El correo ya está registrado.');
 */
export class AppError extends Error {
  constructor(statusCode, code, message, fieldErrors) {
    super(message);
    this.name = 'AppError';
    this.statusCode = statusCode;
    this.code = code;
    this.fieldErrors = fieldErrors;
  }
}

/**
 * Construye SIEMPRE la misma estructura de error para que el frontend la procese igual:
 * { success, statusCode, error, message, code, timestamp, path }
 * El path NO incluye la query string (?email=...), que puede contener datos personales.
 */
export function buildErrorPayload(req, statusCode, code, message, fieldErrors) {
  return {
    success: false,
    statusCode,
    error: STATUS_CODES[statusCode] || 'Error',
    message,
    code,
    ...(fieldErrors ? { fieldErrors } : {}),
    timestamp: new Date().toISOString(),
    path: req.originalUrl.split('?')[0]
  };
}

// 404: ninguna ruta coincidió con la petición
export function notFoundHandler(req, res) {
  res.status(404).json(
    buildErrorPayload(req, 404, 'ROUTE_NOT_FOUND', 'La ruta solicitada no existe en este servidor.')
  );
}

// Traduce los errores de Mongoose (Sesión 10) a errores de la aplicación
function fromMongooseError(err) {
  // Falló una regla del esquema (required, minlength, enum, match...)
  if (err.name === 'ValidationError' && err.errors) {
    const fieldErrors = Object.fromEntries(
      Object.entries(err.errors).map(([field, detail]) => [
        field,
        // Los errores de tipo traen un mensaje técnico en inglés: se reemplaza por uno claro
        detail.name === 'CastError' ? 'El valor no tiene el tipo esperado.' : detail.message
      ])
    );
    return new AppError(400, 'VALIDATION_ERROR', 'Los datos enviados no son válidos.', fieldErrors);
  }
  // Un valor no se pudo convertir al tipo del esquema (ej. "abc" en un campo Number)
  if (err.name === 'CastError') {
    return new AppError(400, 'INVALID_VALUE', 'Los datos enviados no son válidos.', {
      [err.path]: 'El valor no tiene el tipo esperado.'
    });
  }
  // Índice único violado (ej. dos servicios con el mismo code)
  if (err.code === 11000) {
    const fieldErrors = Object.fromEntries(
      Object.keys(err.keyValue ?? {}).map((field) => [field, 'Ya existe un registro con este valor.'])
    );
    return new AppError(409, 'DUPLICATE_KEY', 'Ya existe un registro con ese valor único.', fieldErrors);
  }
  return null;
}

// Manejador global: Express lo reconoce porque recibe 4 parámetros (err, req, res, next)
export function errorHandler(err, req, res, next) {
  if (res.headersSent) return next(err);

  // JSON malformado enviado por el cliente (lo lanza express.json())
  if (err.type === 'entity.parse.failed') {
    return res.status(400).json(
      buildErrorPayload(req, 400, 'INVALID_JSON', 'El cuerpo de la petición no es un JSON válido.')
    );
  }

  // Cuerpo más grande que el límite configurado en express.json({ limit })
  if (err.type === 'entity.too.large') {
    return res.status(413).json(
      buildErrorPayload(req, 413, 'PAYLOAD_TOO_LARGE', 'El cuerpo de la petición supera el tamaño permitido.')
    );
  }

  // Errores controlados: los nuestros y los de Mongoose ya traducidos
  const appError = err instanceof AppError ? err : fromMongooseError(err);
  if (appError) {
    return res.status(appError.statusCode).json(
      buildErrorPayload(req, appError.statusCode, appError.code, appError.message, appError.fieldErrors)
    );
  }

  // Error inesperado: el detalle va al log del servidor, NUNCA al cliente
  console.error('🔥 [Unhandled Exception]:', err);
  return res.status(500).json(
    buildErrorPayload(req, 500, 'INTERNAL_ERROR', 'Ocurrió un error inesperado. Intente nuevamente.')
  );
}
Solo cambian dos cosas respecto a la Sesión 08 ① La función nueva fromMongooseError(err), debajo de notFoundHandler. ② En errorHandler, el bloque if (err instanceof AppError) { … } se reemplaza por const appError = … ; if (appError) { … }.
ValidationError → 400 un mensaje por campo en fieldErrors.
CastError → 400 "hours": "muchas" no es número.
11000 → 409 el equivalente MongoDB del 23505 (Sesión 09).

const EMAIL_REGEX = /^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/;
const UUID_REGEX = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;
const OBJECT_ID_REGEX = /^[0-9a-f]{24}$/i;

// Texto, máximo 150 caracteres (VARCHAR(150) de la tabla users) y formato de correo
export const isValidEmail = (value) =>
  typeof value === 'string' && value.trim().length <= 150 && EMAIL_REGEX.test(value.trim());

// Un id inválido se rechaza con 400 aquí; si llegara a PostgreSQL provocaría el error 22P02 (500)
export const isUuid = (value) => typeof value === 'string' && UUID_REGEX.test(value);

// ObjectId de MongoDB: exactamente 24 caracteres hexadecimales.
// (mongoose.isValidObjectId también acepta cualquier texto de 12 caracteres, por eso usamos regex)
export const isObjectId = (value) => typeof value === 'string' && OBJECT_ID_REGEX.test(value);

/**
 * Límite de resultados para listados: entero entre 1 y max.
 * Ningún listado devuelve la colección completa: sin tope, una petición podría traer millones de documentos.
 */
export function parseLimit(value, { defaultLimit = 20, max = 50 } = {}) {
  if (value === undefined) return defaultLimit;
  const limit = typeof value === 'string' && /^\d+$/.test(value) ? Number(value) : NaN;
  if (!Number.isInteger(limit) || limit < 1 || limit > max) {
    throw new AppError(400, 'VALIDATION_ERROR', 'Los datos enviados no son válidos.', {
      limit: `Debe ser un número entero entre 1 y ${max}.`
    });
  }
  return limit;
}

// Campos que el cliente NUNCA puede escribir (los gestiona el servidor)
const PROTECTED_FIELDS = ['_id', 'type', 'createdAt', 'updatedAt', '__v', 'views'];

// Copia solo los campos editables. Las llaves que empiezan por "$" se descartan:
// un body como { "$set": {...} } no debe convertirse en un operador de MongoDB.
const pickEditable = (body) =>
  Object.fromEntries(

    throw new AppError(400, 'VALIDATION_ERROR', 'Los datos enviados no son válidos.', {
      type: `Debe ser uno de: ${CONTENT_TYPES.join(', ')}.`
    });
  }
};

/**
 * GET /api/content/published?type=service&limit=20   (PÚBLICO)
 * Contenidos visibles en la Landing Page: solo active: true.

export async function getPublishedContents(req, res) {
  const filter = { active: true };
  if (req.query.type !== undefined) {
    assertContentType(req.query.type);
    filter.type = req.query.type;
  }
  const limit = parseLimit(req.query.limit);

  // Ordenar por priority solo funciona dentro de los banners: en MongoDB, los documentos
  // SIN el campo quedan ANTES que los números en orden ascendente. Por eso se agrupa por type primero.
  const data = await Content.find(filter)
    .sort({ type: 1, priority: 1, createdAt: -1 })
    .limit(limit)
    .select('-__v')
    .lean(); // Objetos JS planos: más rápido para solo lectura

  res.json({ success: true, data, meta: { count: data.length, limit } });
}

/**
 * GET /api/dev/content?active=false&type=banner&limit=20   (LABORATORIO · admin en la Semana 3)
 * Incluye borradores: es la vista del panel administrativo.
 */
export async function listContents(req, res) {
  const filter = {};
  if (req.query.type !== undefined) {
    assertContentType(req.query.type);
    filter.type = req.query.type;
  }
  if (req.query.active !== undefined) {
    if (req.query.active !== 'true' && req.query.active !== 'false') {
      throw new AppError(400, 'VALIDATION_ERROR', 'Los datos enviados no son válidos.', { active: 'Debe ser true o false.' });
    }
    filter.active = req.query.active === 'true';
  }
  const limit = parseLimit(req.query.limit);

  const data = await Content.find(filter).sort({ updatedAt: -1 }).limit(limit).select('-__v').lean();
  res.json({ success: true, data, meta: { count: data.length, limit } });
}

/**
 * POST /api/dev/content   Body: { "type": "service", ...campos del tipo }
 */
export async function createContent(req, res) {
  const { type } = req.body ?? {};
  assertContentType(type);

  // El discriminator correcto valida los campos propios del tipo
  const ContentModel = Content.discriminators[type];
  const doc = await ContentModel.create(pickEditable(req.body));

  res.status(201).json({ success: true, data: doc.toObject({ versionKey: false }) });
}

/**
 * PATCH /api/dev/content/:id   Body: campos a modificar (actualización parcial)
 */
export async function updateContent(req, res) {
  const { id } = req.params;
  if (!isObjectId(id)) throw invalidId();

  const doc = await Content.findById(id); // Devuelve la instancia del discriminator correcto
  if (!doc) throw contentNotFound();

  if (req.body?.type !== undefined && req.body.type !== doc.type) {
    throw new AppError(422, 'CONTENT_TYPE_IMMUTABLE', 'El tipo de un contenido no se puede cambiar; cree uno nuevo.');
  }

  // doc.set + doc.save ejecuta TODAS las validaciones del esquema y actualiza updatedAt
  doc.set(pickEditable(req.body));
  await doc.save();

  res.json({ success: true, data: doc.toObject({ versionKey: false }) });
}

/**
 * DELETE /api/dev/content/:id
 */
export async function deleteContent(req, res) {
  const { id } = req.params;
  if (!isObjectId(id)) throw invalidId();

  const deleted = await Content.findByIdAndDelete(id);
  if (!deleted) throw contentNotFound();

  res.status(204).end(); // 204 No Content: borrado exitoso, sin cuerpo
}
Content.discriminators[type]Elige el esquema del tipo, que aplica sus validaciones y fija type automáticamente.
¿Por qué no findByIdAndUpdate?No ejecuta por defecto las validaciones del discriminator. doc.set() + doc.save() valida todo el documento.
400 · 404 · 422Id mal formado, documento inexistente y regla de negocio (el tipo no cambia) son tres errores distintos.

¿Qué tanto dominas la Sesión 10?

Responde antes de la sustentación. Cada opción muestra al instante si es correcta y por qué: úsala para detectar qué repasar.

¿Qué recibe el controlador con ?type[$ne]=banner?

  • El texto "banner"
  • El objeto { $ne: "banner" }: un operador que alteraría el filtro
  • Un error 400 automático de Express
  • undefined

Creaste un contenido y no aparece en /api/content/published. ¿Por qué?

  • Falló el índice
  • Todo contenido nuevo nace como borrador (active: false)
  • Mongoose tarda un minuto en publicar
  • Falta reiniciar el servidor

¿Por qué el esquema rechaza ctaUrl: "javascript:alert(1)"?

  • Porque es demasiado largo
  • Para evitar un XSS cuando React lo use en el href del botón
  • Porque MongoDB no guarda dos puntos
  • Por el límite de 100 kb
