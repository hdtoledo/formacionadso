Regla de Oro en Arquitectura de Software:

Una capa inferior nunca debe conocer a una capa superior. El módulo de bases de datos (config/db.js) desconoce por completo la existencia de peticiones HTTP, rutas o de Express. Solo exporta clientes de conexión.

Rendimiento & Manejo de Recursos en el Servidor

¿Por qué un Connection Pool y NO un cliente por petición?

Peligro: Crear un Client por Petición

Abrir una conexión TCP con PostgreSQL requiere un costoso Three-Way Handshake de red, negociación SSL/TLS, autenticación de usuario y asignación de memoria RAM en el servidor de base de datos.

100 peticiones concurrentes = 100 procesos creados en PostgreSQL = Crash del Servidor (Out of Memory).
Solución Enterprise: Connection Pool

El Pool crea un número controlado de conexiones persistentes (por ejemplo, 10 clientes). Cuando llega una petición, toma un cliente pre-calentado, ejecuta la query y lo devuelve inmediatamente al pool para la siguiente solicitud.

1,000 peticiones = reutilizan 10 clientes físicos en milisegundos con latencia cercana a 0.
Driver Oficial 'pg' (node-postgres)

Anatomía del Pool de PostgreSQL (pg.Pool)

max: 10

Número máximo de conexiones simultáneas que el pool mantendrá abiertas con la base de datos.

idleTimeoutMillis: 30000

Tiempo en milisegundos (30s) que un cliente puede permanecer ocioso antes de ser destruido para liberar memoria.

connectionTimeout: 5000

Tiempo máximo de espera para obtener un cliente disponible antes de abortar con error de timeout.

import pg from 'pg';
const { Pool } = pg;

export const pool = new Pool({
  host: process.env.PG_HOST,
  port: parseInt(process.env.PG_PORT, 10),
  database: process.env.PG_DATABASE,
  user: process.env.PG_USER,
  password: process.env.PG_PASSWORD,
  max: 10,
  idleTimeoutMillis: 30000
});

pool.on('error', (err) => console.error('Error en cliente ocioso:', err));
Mongoose ODM & MongoDB Atlas Cluster M0

El Patrón Singleton en Mongoose & Ciclo de Vida

A diferencia del driver nativo de PG donde se crea un pool explícito, Mongoose gestiona internamente su propio Connection Pool bajo un patrón Singleton en el objeto global mongoose.connection.

Estados de Conexión (readyState):
0: Disconnected
1: Connected (Listo)
2: Connecting
3: Disconnecting
import mongoose from 'mongoose';

// Listeners de Ciclo de Vida del Clúster Atlas
mongoose.connection.on('connected', () => {
  console.log('🍃 MongoDB Atlas Conectado exitosamente');
});

mongoose.connection.on('error', (err) => {
  console.error('❌ MongoDB Error:', err.message);
});

await mongoose.connect(process.env.MONGO_URI, {
  serverSelectionTimeoutMS: 5000
});

Gestión Defensiva de Variables de Entorno (dotenv)

El archivo .env contiene credenciales reales (contraseñas de BD, tokens de Atlas) y JAMÁS se sube a GitHub. Debe estar ignorado en .gitignore.

El archivo .env.example sí se versiona en Git; sirve como contrato y plantilla para que cualquier compañero de equipo sepa qué variables debe configurar.

Paso a Paso 2C · Funciones de Conexión y Desconexión Controlada

Live Coding 2C: connectDatabases() & disconnectDatabases() 

export async function connectDatabases() {
  console.log('🔌 [ADSO DUAL DB] Inicializando conexiones...');

  // A. Verificación PostgreSQL
  try {
    const res = await pool.query('SELECT NOW() AS t, current_database() AS db');
    console.log(`✅ [PostgreSQL Conectado] Base: "${res.rows[0].db}"`);
  } catch (err) {
    console.error(`❌ [PostgreSQL Falló Conexión]: ${err.message}`);
  }

  // B. Inicialización MongoDB Atlas
  try {
    await mongoose.connect(config.mongo.uri, { serverSelectionTimeoutMS: 5000 });
    console.log(`✅ [MongoDB Atlas Conectado] Base: "${mongoose.connection.name}"`);
  } catch (err) {
    console.error(`❌ [MongoDB Falló Conexión]: ${err.message}`);
  }
}

export async function disconnectDatabases() {
  await pool.end();
  await mongoose.connection.close();
  console.log('🔒 Ambas bases de datos cerradas correctamente');
}
Paso a Paso 3 · Controlador de Diagnóstico en Tiempo Real

Live Coding 3: src/controllers/healthController.js 

import { pool, mongoose } from '../config/db.js';

export async function getHealthStatus(req, res) {
  const services = {
    api: { status: 'up', uptime_seconds: Math.floor(process.uptime()) },
    postgres: { status: 'down', latency_ms: null, error: null },
    mongodb: { status: 'down', latency_ms: null, error: null }
  };

  // 1. Evaluar PostgreSQL Pool
  const pgStart = Date.now();
  try {
    await pool.query('SELECT NOW()');
    services.postgres.latency_ms = Date.now() - pgStart;
    services.postgres.status = 'healthy';
  } catch (err) {
    services.postgres.latency_ms = Date.now() - pgStart;
    services.postgres.error = err.message;
  }

  // 2. Evaluar MongoDB Atlas
  const mongoStart = Date.now();
  try {
    if (mongoose.connection.readyState === 1 && mongoose.connection.db) {
      await mongoose.connection.db.admin().ping();
      services.mongodb.latency_ms = Date.now() - mongoStart;
      services.mongodb.status = 'healthy';
    }
  } catch (err) {
    services.mongodb.latency_ms = Date.now() - mongoStart;
    services.mongodb.error = err.message;
  }

  const isHealthy = services.postgres.status === 'healthy' && services.mongodb.status === 'healthy';
  return res.status(isHealthy ? 200 : 503).json({
    status: isHealthy ? 'healthy' : 'degraded',
    timestamp: new Date().toISOString(),
    services
  });
}

Paso a Paso 5 · Pipeline de Middlewares & Manejadores de Error

Live Coding 5: src/app.js 

import express from 'express';
import cors from 'cors';
import morgan from 'morgan';
import healthRoutes from './routes/healthRoutes.js';

const app = express();

// 1. Middlewares Globales
app.use(cors());
app.use(express.json());
app.use(morgan('dev'));

// 2. Montaje de Enrutadores
app.use('/api/health', healthRoutes);

// 3. Manejador de Rutas No Encontradas (404)
app.use((req, res) => {
  res.status(404).json({ error: 'NotFound', message: `Ruta [${req.method}] ${req.originalUrl} no existe.` });
});

// 4. Manejador Global de Excepciones No Controladas (500)
app.use((err, req, res, next) => {
  console.error('🔥 Error:', err.stack);
  res.status(500).json({ error: 'InternalServerError', message: 'Error interno en el servidor.' });
});

export default app;
Paso a Paso 6 · Orquestador del Servidor HTTP

Live Coding 6: src/server.js & Graceful Shutdown 

import app from './app.js';
import { config } from './config/environment.js';
import { connectDatabases, disconnectDatabases } from './config/db.js';

async function bootstrap() {
  await connectDatabases();

  const server = app.listen(config.port, () => {
    console.log(`🚀 Servidor activo en: http://localhost:${config.port}`);
  });

  const handleShutdown = async (signal) => {
    console.log(`\n⚠️  ${signal} recibido. Cerrando conexiones limpiamente...`);
    server.close(async () => {
      await disconnectDatabases();
      process.exit(0);
    });
  };

  process.on('SIGINT', () => handleShutdown('SIGINT'));
  process.on('SIGTERM', () => handleShutdown('SIGTERM'));
}

bootstrap();

Análisis del Payload: GET /api/health (HTTP 200 OK)

Este endpoint permite a balanceadores de carga (como NGINX o AWS ALB) y a herramientas de monitoreo verificar la operatividad de toda la pila en un solo round-trip.

Status 200 OK

Ambas bases de datos responden consultas con latencias nominales (< 200ms).

Status 503 Service Unavailable

Si PostgreSQL o MongoDB Atlas no responden, el servicio se marca degraded/unhealthy.
