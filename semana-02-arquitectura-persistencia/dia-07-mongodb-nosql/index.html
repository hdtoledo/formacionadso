¿Cómo Usan la Persistencia Políglota las Grandes Empresas?

Ningún unicornio tecnológico almacena todo en una sola base de datos. La arquitectura que implementamos en ADSO es el mismo patrón que opera a escala mundial:

UBER Movilidad
PostgreSQL / Schemaless: Cuentas de usuarios, transacciones de viaje y facturación bancaria (ACID).
NoSQL (Cassandra / Mongo): Telemetría GPS en tiempo real de vehículos y logs de eventos de app.
NETFLIX Streaming
RDBMS (PostgreSQL/Aurora): Suscripciones, cobros mensuales y gestión de contratos de contenido.
NoSQL (Cassandra / MongoDB): Catálogo multimedia dinámico, carátulas personalizadas y listas de usuario.
MERCADO LIBRE E-Commerce
RDBMS Relacional: Mercado Pago, saldos contables, balances bancarios y ledger de cobros.
NoSQL Documental: Fichas de producto con atributos heterogéneos (talla, procesador, color, etc.).
Conclusión de Ingeniería: Use SQL para integridad financiera y autenticación; use NoSQL para contenidos, catálogos heterogéneos y flexibilidad sin bloqueos.

Matriz de Decisión: ¿Cuándo Usar SQL vs Cuándo NoSQL?

Evite el error de principiante de afirmar que "una base de datos es mejor que otra". Cada motor resuelve una necesidad matemática y operacional distinta:

Característica Técnica PostgreSQL (Relacional SQL) MongoDB (NoSQL Documental) En Nuestro Proyecto ADSO
Estructura de Datos Tablas con filas y columnas predefinidas Documentos BSON / JSON flexibles users vs contents
Transacciones ACID estricto a nivel multi-tabla ACID a nivel de documento individual Auth sensible vs Landing masiva
Cambios de Esquema ALTER TABLE (requiere migración) Dinámico: cada doc puede tener nuevos campos Agregar nuevos servicios en 1 seg
Relaciones & Cruces JOINs altamente eficientes con FKs Embebidos (subdocumentos) o referencias Tokens vinculados a Users
Escalabilidad Vertical (CPU/RAM) + Réplicas Read-Only Horizontal nativa (Sharding distribuido) Atlas M0 en la Nube
Regla de Oro en Producción: Si el dato involucra dinero, contraseñas o auditoría legal, use PostgreSQL. Si el dato involucra catálogos de marketing, blogs, analítica o esquemas variables, use MongoDB.
Paradigma NoSQL Documental

De Tablas Relacionales a Documentos Autocontenidos

En SQL, para guardar un servicio con sus tags y requisitos debíamos crear 3 tablas separadas y hacer JOIN. En MongoDB, el documento almacena toda la información junta en formato jerárquico:

ENFOQUE SQL (3 TABLAS SEPARADAS)
-- 1. Tabla servicios
CREATE TABLE services (id INT, name VARCHAR, ...);
-- 2. Tabla tags
CREATE TABLE tags (id INT, name VARCHAR);
-- 3. Tabla intermedia Many-to-Many
CREATE TABLE service_tags (service_id INT, tag_id INT);

Requiere 2 JOINs para obtener los datos completos de un solo servicio.

ENFOQUE MONGODB (1 DOCUMENTO AUTOCONTENIDO)
{
"_id": ObjectId("670f...a1"),
"name": "Desarrollo Full Stack",
"tags": ["express", "mongodb", "react"],
"metadata": { "hours": 120, "capacity": 30 }
}

Una sola lectura recupera toda la entidad sin sobrecargar la CPU con JOINs.

Rendimiento en Lectura: Los documentos embebidos permiten servir las peticiones de la Landing Page en menos de 5 milisegundos.
BSON: Binary JSON

¿Qué es BSON y Cómo Funciona el ObjectId?

MongoDB almacena los datos en BSON (Binary JSON), una extensión binaria de JSON que admite tipos de datos adicionales como fechas nativas, enteros de 64 bits y el identificador universal ObjectId de 12 bytes:

Anatomía de los 12 Bytes del ObjectId

Al igual que el UUIDv4 en PostgreSQL, el ObjectId previene ataques de enumeración (IDOR) y garantiza unicidad global sin depender de un auto-increment:

4 Bytes · Timestamp Fecha/hora exacta en segundos Unix
5 Bytes · Random Value Único por proceso/máquina servidora
3 Bytes · Counter Contador incremental inicializado al azar
💡 Ventaja: Permite ordenar cronológicamente por _id sin necesidad de un campo adicional.

Tipos BSON vs JSON Estándar

  • ISODate("...") Maneja zonas horarias reales (UTC) a diferencia del string plano de JSON.
  • NumberInt / NumberLong Diferencia entre enteros de 32 bits, 64 bits y flotantes con alta precisión.
  • Array & Subdocument Anidamiento profundo indexable y consultable mediante dot-notation.

Database as a Service (DBaaS)

MongoDB Atlas: Persistencia Cloud Totalmente Administrada

En lugar de instalar y configurar manualmente un demonio mongod en su sistema operativo, utilizaremos MongoDB Atlas, la plataforma en la nube oficial de MongoDB:

Zero Mantenimiento

Atlas se encarga de parches de seguridad, copias de seguridad automáticas, cifrado en reposo y aprovisionamiento de hardware sin intervención manual.

Seguridad por Defecto

Conexión obligatoria con TLS/SSL v1.3, firewall de IP Access List y autenticación SCRAM-SHA-256 para prevenir accesos no autorizados.

Clúster M0 Gratuito

El nivel M0 ofrece 512 MB de almacenamiento gratuito de por vida, ideal para el desarrollo del proyecto formativo y pruebas en el aula.

Multi-Cloud: Atlas corre sobre AWS, Google Cloud o Microsoft Azure con la misma API estándar.
Aprovisionamiento Paso a Paso · Atlas 1 de 4

Paso 1: Crear el Clúster M0 Sandbox en Atlas

Siga estas instrucciones exactas en su navegador para crear la infraestructura sin costo:

1 Selección de Plan y Proveedor Cloud

  1. Inicie sesión en mongodb.com/atlas.
  2. Haga clic en el botón verde + Create.
  3. En la pantalla de selección, escoja la opción M0 Free (512 MB Storage).
  4. Seleccione como proveedor AWS y región us-east-1 (N. Virginia) o la recomendada con menor latencia.
  5. Asigne un nombre representativo: adso-cluster o Cluster0.

Precaución Pedagógica en Aula

Nunca seleccione planes M10 o dedicados que soliciten tarjeta de crédito. El nivel M0 Free Tier es gratuito de forma permanente y suficiente para persistir miles de documentos de catálogo.

⏱️ Tiempo de aprovisionamiento: Atlas toma entre 1 a 3 minutos en desplegar los contenedores en AWS.
Seguridad y Credenciales · Atlas 2 de 4

Paso 2: Crear el Usuario de Base de Datos

El usuario del portal de Atlas no es el usuario de base de datos. Debemos crear un usuario con privilegios acotados:

2 Configuración de Database Access

  1. En el menú lateral izquierdo, vaya a Security > Database Access.
  2. Haga clic en + Add New Database User.
  3. Método de autenticación: Password.
  4. Username: adso_user.
  5. Password: Establezca una clave robusta (e.g., Secret2026) y guárdela.
  6. Database User Privileges: Seleccione Read and write to any database.
  7. Haga clic en Add User.

Principio de Mínimo Privilegio (PoLP)

Nunca asigne el rol de Atlas Admin a un usuario de aplicación. En entornos profesionales, cada servicio backend tiene su propio usuario con permisos exclusivos sobre su base de datos.

Seguridad Perimetral · Atlas 3 de 4

Paso 3: Reglas de Red e IP Access List

MongoDB Atlas bloquea por defecto todas las conexiones entrantes mediante un firewall cloud estricto:

3 Habilitar Acceso en Network Access

  1. En el menú lateral izquierdo, vaya a Security > Network Access.
  2. Haga clic en + Add IP Address.
  3. Para el ambiente formativo del aula SENA (donde la IP pública de la sala puede rotar): haga clic en Allow Access From Anywhere (0.0.0.0/0).
  4. En el campo de comentario, escriba: ADSO Laboratorio Garzón.
  5. Haga clic en Confirm.

Diferencia: Producción vs Ambiente de Aula

En producción, 0.0.0.0/0 está prohibido: solo se autoriza la IP estática del servidor de aplicaciones (AWS EC2, Render, Vercel) o se usa VPC Peering. En aula, lo usamos para que todos los aprendices puedan conectarse sin bloqueos de NAT.

🛡️ El usuario y la contraseña siguen protegiendo la base de datos aun con acceso abierto en red.
Connection String · Atlas 4 de 4

Paso 4: Obtener la URI de Conexión SRV

El Connection String es el puente criptográfico que conecta tanto a MongoDB Compass como a nuestro futuro backend Express con el clúster:

Copiar la URI desde el botón Connect

En la pestaña Database Deployments, haga clic en el botón Connect, seleccione la opción Compass y copie la cadena de conexión:

Lenguaje de Consultas NoSQL

Introducción a MQL: Consultas Declarativas Basadas en JSON

En lugar de sentencias de texto plano como SELECT * FROM ..., en MongoDB las consultas son objetos JSON estructurados que representan predicados lógicos:

Estructura de la Barra de Filtro en Compass

En la parte superior de la colección en Compass encontrará los campos de consulta:

  • Filter: Documento JSON con las condiciones de búsqueda.
  • Project: Qué campos mostrar (1) o esconder (0).
  • Sort: Orden ascendente (1) o descendente (-1).
  • Limit: Número máximo de documentos a retornar.
  • Skip: Paginación para saltar N documentos.
# Equivalencia Visual: SQL vs MQL
-- SQL:
SELECT * FROM contents WHERE type = 'service' AND active = true;
// MQL (MongoDB Filter):
{ type: "service", active: true }

La coincidencia por defecto entre campos separados por coma equivale a un operador lógico AND.

Laboratorio de Consultas · Nivel 1

MQL Práctico 1: Filtros de Igualdad, $and y $or

Escriba y ejecute estos filtros en la barra de consulta de MongoDB Compass:

Reto 1: Filtrar Todos los Servicios Activos Igualdad Simple
{ type: "service", active: true }

Retorna los servicios listos para ser mostrados en la página principal.

Reto 2: Filtrar Banners Activos con Prioridad Alta (1) Filtro Compuesto
{ type: "banner", priority: 1, active: true }

Ubica el banner principal del hero de la Landing Page.

Reto 3: Operador Lógico $or (Banners O Testimonios) Operador $or
{ $or: [ { type: "banner" }, { type: "testimonial" } ] }

Retorna los documentos que cumplan al menos una de las dos condiciones.

Laboratorio de Consultas · Nivel 2

MQL Práctico 2: Operadores de Comparación e Inclusión

Filtre datos analíticos y matrices categóricas con los operadores nativos de MongoDB:

Reto 4: Operador $in (Servicios de Software o Agroindustria) Inclusión en Array
{ type: "service", category: { $in: ["software", "agroindustria"] } }

Equivale a WHERE category IN ('software', 'agroindustria') en SQL.

Reto 5: Operador $gte (Testimonios con Calificación 5 Estrellas) Mayor o Igual
{ type: "testimonial", rating: { $gte: 5 } }

Selecciona los testimonios más destacados para la sección de reputación institucional.

Reto 6: Operador $gt (Servicios Populares con Más de 400 Visitas) Comparación Numérica
{ type: "service", views: { $gt: 400 } }

Ideal para construir la sección de "Servicios Más Solicitados".

Optimización de Tráfico de Red · Nivel 3

MQL Práctico 3: Proyecciones, Sort & Paginación

Enviar campos innecesarios por la red satura el ancho de banda. Las proyecciones definen exactamente qué propiedades viajan al cliente:

Proyección (Campo Project en Compass)

Indique 1 para incluir o 0 para excluir:

// Project:
{ name: 1, category: 1, views: 1, _id: 0 }

Retorna únicamente el nombre, la categoría y las vistas, excluyendo el _id.

Ordenamiento (Campo Sort en Compass)

Indique 1 para ascendente o -1 para descendente:

// Sort (Mayor a Menor Popularidad):
{ views: -1 }

Ordena los servicios desde el más visto hasta el menos visto para el top comercial.

Agilidad de Negocio sin Caídas

Modificación Dinámica en Caliente: Ventaja Zero Downtime

Imagine que el centro SENA decide lanzar un nuevo tipo de contenido: eventos formativos con fecha y lugar. ¿Qué pasaría en SQL vs MongoDB?

ENFOQUE SQL (ALTO RIESGO)

Bloqueo DDL en Producción

Requiere crear una migración ALTER TABLE o nueva tabla, detener el tráfico durante el despliegue o arriesgarse a bloqueos de tabla (table lock) con millones de usuarios conectados.

ENFOQUE MONGODB (CERO DOWNTIME)

Inserción Inmediata de Nuevo Esquema

Basta con insertar el nuevo documento con type: "event" en la colección contents. Ninguna consulta existente se rompe y el frontend ya puede consumirlo al instante.

db.contents.insertOne({ type: "event", title: "Hackathon Suaza 2026", active: true }) ⟶ Éxito sin reiniciar el motor

Montaje Paso a Paso: Construcción en Repositorio Personal

Aclaración Metodológica Importante: No existen plantillas ni talleres descargables prefabricados. El taller formativo es realizar cada montaje paso a paso lección tras lección en su entorno de desarrollo local y cargar todo el proceso a su repositorio personal de GitHub con sus respectivos commits atómicos.

Estructure el subárbol NoSQL y complete los 4 hitos registrando cada commit atómico:

HITO 1: Estructura & Semilla BSON Commit 1

Crear carpeta database/nosql/ y registrar el archivo 01_content_seed.json con los 10 documentos polimórficos.

git commit -m "feat(nosql): estructura database/nosql y seed de contenidos"
HITO 2: Clúster Atlas & Whitelist Commit 2

Crear clúster M0 en Atlas, usuario adso_user y configurar regla de red 0.0.0.0/0.

git commit -m "config(atlas): cluster m0 atlas y whitelist de red"
HITO 3: Base de Datos & Colección en Compass Commit 3

Conectar Compass vía SRV, crear adso_polyglot_db, colección contents e importar los 10 documentos.

git commit -m "feat(compass): creacion de adso_polyglot_db y coleccion contents"
HITO 4: Consultas MQL & Push Final Commit 4 + Push

Ejecutar consultas con filtros ($in, $gt), proyección y enviar cambios a GitHub.

git commit -m "test(mql): validacion de consultas filtradas y esquema polimorfico" && git push -u origin main
Guía Operativa en Aula · Ejecución Paso a Paso

Flujo de Terminal: Creación, Versionamiento y Sincronización

Siga la secuencia de comandos en su terminal para garantizar que su repositorio quede en el estado exacto requerido para la sesión:

# 1. Asegurar estar en la raíz de su repositorio personal
cd ~/mi-proyecto-adso
# 2. Crear subcarpeta NoSQL y archivo seed
mkdir -p database/nosql
# (Copie o cree el archivo database/nosql/01_content_seed.json)
# 3. Primer commit: Semilla BSON
git add database/nosql/01_content_seed.json
git commit -m "feat(nosql): estructura database/nosql y seed de contenidos"
# 4. Segundo commit: Configuración Atlas (actualice su README si documenta la URI)
git commit -m "config(atlas): cluster m0 atlas y whitelist de red"
# 5. Tercer commit: Creación de BD y Colección
git commit -m "feat(compass): creacion de adso_polyglot_db y coleccion contents"
# 6. Cuarto commit y Push a su rama principal en GitHub
git commit -m "test(mql): validacion de consultas filtradas y esquema polimorfico"
git push -u origin main

Cierre de la Sesión 07

Resumen Técnico & Glosario de Aprendizaje

Conceptos fundamentales que deben quedar incorporados en el léxico técnico de cada aprendiz:

BSON Representación binaria de JSON utilizada internamente por MongoDB para almacenar datos y tipos avanzados.
ObjectId Identificador de 12 bytes con timestamp, aleatoriedad y contador. Inmune a enumeración IDOR.
MQL MongoDB Query Language. Sintaxis declarativa basada en JSON con operadores de filtro ($in, $gt).
Polimorfismo Capacidad de almacenar documentos con estructuras y atributos heterogéneos dentro de la misma colección.
